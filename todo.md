### P0-2a. Реализовать оптимистическую блокировку (`If-Match`), объявленную в трёх местах

**Проблема.** Инвариант «версия» объявлен в модели, но не исполняется нигде:

- 02-tactical.md:36 — шаг 1 проверки: «версия: `actor.IfMatch == l.Version`, иначе `ErrConflict` (409)»;
- `domain.Line.Authorize()` — код проверки есть (line.go:105-107), но метод не вызывается (см. P0-1);
- `api/openapi.yaml:15` — «Изменения строк требуют актуальной версии (`If-Match`, этап 6 плана) — иначе `409 conflict`».

Фактически:

- поиск `where version = $` по всему Go-коду вне тестов — **0 совпадений**;
- обработка заголовка `If-Match` в Go — **0 совпадений**;
- `ifMatch` в PWA — **0 совпадений**;
- конкурентность обеспечивается пессимистично: `SELECT … FOR UPDATE` в 26 местах
  (arm/lines.go:722, reserve.go:43, fifo.go:48, jobs.go:198 и далее).

То есть `version` инкрементируется (arm/arm.go:173, lines.go:1062, jobs.go:211, notices.go:46),
но никогда не проверяется. Клиент не может получить 409 по устаревшей версии, хотя контракт
это обещает. При этом `FOR UPDATE` держит блокировку на время транзакции и не защищает
от «потерянного обновления» между чтением формы и отправкой — типовой сценарий для АРМ.

**Что сделать.**

1. Включить проверку версии в путь записи строки: сравнивать `If-Match` с `arm.line.version`
   в `UPDATE … WHERE id = $1 AND version = $2`, при 0 затронутых строк возвращать 409 `conflict`.
2. Прокинуть заголовок `If-Match` из HTTP-слоя в команду (`domain.Actor` расширить полем
   `IfMatch` — см. P2-7) и в `domain.Line.Authorize()`.
3. На клиенте отправлять `version`, полученную с `GET /lines/{id}`, и обрабатывать 409
   (показать «строка изменена другим пользователем» и перечитать).
4. Добавить `If-Match` в описание операций изменения строки в `api/openapi.yaml` —
   сейчас он упомянут только в прозе описания (openapi.yaml:15).

**Критерий готовности:** одновременное изменение одной строки двумя сессиями даёт 409 второму
клиенту; тест на конкурентность зелёный; `If-Match` описан в схеме операций.

## 7. Критерии приёмки архитектуры

Считать работу завершённой, когда одновременно выполнено:

1. `domain` не импортирует внутренние пакеты; `application` не импортирует `arm`, `pgx`, `pgxpool`.
2. В `internal/application` нет SQL; в `domain` нет `float64` для денег.
3. `domain.Line` (и остальные агрегаты из 02-tactical.md:48-62) вызываются из продакшн-кода.
4. Таблица переходов и правило матрицы существуют в одной копии на бэкенде.
5. У каждого события из events.go есть обработчик; список триггеров, меняющих бизнес-данные, пуст.
6. Пакет `arm` отсутствует; самый крупный файл < 400 строк; то же для `pwa/src`.
7. Архитектурные проверки выполняются в CI и падают при нарушении.
8. `types.gen.go` содержит серверный интерфейс, обработчики его реализуют.
9. `If-Match` исполняется: устаревшая версия даёт 409, а не молчаливую перезапись.
10. Значения `arm.line.status` ограничены списком допустимых на уровне схемы (CHECK или enum).
