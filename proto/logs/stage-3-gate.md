## Цепочка `happy` проходит в РЕАЛЬНОМ браузере

```
загрузка листа → new → задание (M4) → ordered → оплата (M7) → paid
```

Тест `e2e/happy-chain.spec.ts` кликает по кнопкам и читает статус из разметки.

фрагмента после swap, реальные клики, загрузка библиотеки.

## Дефекты, найденные при работе

### 1. Устаревший сервер держал порт — все 6 e2e падали с 404

Сервер прототипа, запущенный в этапе 0, продолжал работать на 18190. Playwright с
`reuseExistingServer` его переиспользовал, и новые UI-маршруты отвечали **404**.
Диагностика заняла один шаг потому, что Playwright сохраняет снимок страницы:
в `error-context.md` было ровно `404 Not Found`, а не «элемент не найден».

**Урок:** `reuseExistingServer` удобен, но опасен при долгоживущих фоновых серверах.
Фоновые задачи надо останавливать, когда они перестают быть нужны.

### 2. `bun test` подхватывал Playwright-спеки

`bun test` по умолчанию берёт и `*.spec.ts` — то есть `e2e/happy-chain.spec.ts`.
Тест запускался раннером Bun и падал. Исправлено: `bun test tests --parallel=1`.

### 3. `import.meta.dir` недоступен в транспайлере Playwright

`globalSetup` падал с «paths[0] must be of type string». Заменено на `process.cwd()`.

### 4. `bun` не запускается через `execFileSync`

В `PATH` лежит `bun.ps1` (обёртка npm) — Node её не исполняет, падает
`spawnSync bun ENOENT`. Путь ищется явно через `APPDATA`.

### 5. Пробел в UI: цепочку нельзя было пройти в браузере

Эндпоинты цепочки существовали, но **в разметке не было ни формы загрузки листа,
ни кнопок канбана**. Добавлены:

| Что | `data-testid` |
|---|---|
| Форма загрузки листа (N1 → M1) | `import-panel`, `import-name`, `import-submit` |
| Задание «В работе» | `chain-job` |
| Канбан снабжения (5 статусов) | `chain-supply-paid`, `-in_transit`, `-acceptance`, `-assembly`, `-assembled` |
| Размещение в ячейку | `chain-cell-select`, `chain-cell` |

Это ровно тот случай, когда интеграционный тест зеленеет, а оператор ничего не может
сделать: тест дёргал эндпоинт напрямую, а кнопки в интерфейсе не было.

## Почему e2e работают без `playwright install`

Используется **системный Chrome** (`channel: 'chrome'`) — не нужна загрузка ≈150 МБ.
В CI ставится штатный chromium. Флаг `--no-proxy-server` обязателен: при заданных в
системе `HTTP_PROXY`/`HTTPS_PROXY` headless Chromium уходит через прокси и не исключает
loopback — получается «health отвечает, а страница висит».

`proxy: { server: 'direct://' }` **не работает**: Playwright принимает это как имя хоста.

## Архитектурный гейт — закрыт досрочно

`scripts/arch.ts` проверяет §12: ≤ 200 строк, ≤ 5 экспортов, ≤ 3 уровней вложенности,
нет `init()`. **36 файлов, 0 нарушений.**

Первая версия проверки врала: считала вложенность по отступам и находила «16 уровней»
внутри SQL-шаблона. Гейт, который врёт, хуже отсутствующего — его перестают читать.
Переписан на разбор текста (вырезает строки, комментарии, шаблоны) и подсчёт блоков
**управления**, а не скобок объектных литералов.

Для зелёного гейта разделены: `lines-mutations` (211 строк) → `lines-fields` +
`lines-transitions`; `operations` (230) → `operations` + `supply`; `ref` (216, 13 экспортов)
→ три файла; `doc` и `transition` и `problem` — по экспортам.
**Схема БД не изменилась:** `db:generate` отвечает «No schema changes».

## Ошибка в собственном скрипте

Замена импортов через PowerShell испортила три файла: `$pair[0]` в цикле оказался
**первым символом строки** — PowerShell разворачивает вложенные массивы. Все `i` стали `m`
(`import` → `mmport`). Файлы восстановлены, замена переведена на построчные вызовы.

**Урок:** массовые правки исходников скриптом надо проверять **сборкой**, а не `Select-String`.
