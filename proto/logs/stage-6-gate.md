## Главное: `bun build` НЕ проверяет типы

В прошлом раунде при разделении `lines-bulk.ts` константа `DELETABLE` осталась
в первом файле. **Оба файла собрались без ошибок** — `bun build` транспилирует,
но не проверяет типы, и дефект стал бы `ReferenceError` только в рантайме.

`tsc --noEmit` нашёл **42 ошибки**. Разбор по категориям:

## Найдено то, что сборка пропускала

### Тип ошибки ВРАЛ о статусе

```ts
return c.json(body, p.status as 400);
```

Приведение к литералу `400` означает: тип ответа говорит 400, а в рантайме приходит
404 или 409. Проверка типов это поймала, `bun build` — нет.

Перебраны три варианта, **все три неверны**, и это записано в код:

| Вариант | Чем плох |
|---|---|
| `as 400` | тип врёт о статусе; маршрут с объявленным 404 не компилируется |
| `as StatusCode` | слишком широко; не компилируется маршрут с объявленным 400 |
| объединение `400\|404\|409\|500` | не компилируется маршрут, объявивший только один статус |
| **`: never`** | ✅ совместим с любым набором объявленных ответов; фактический статус подставляет `c.json` |

Комментарий оставлен, чтобы неудачные варианты не пробовали снова.

### Схемы ошибок были объявлены по-разному

Гейт «один тип ошибки» проверялся через `grep 'type Problem'` = 1 и формально
проходил. Но в маршрутах ответы об ошибках описывались **частичными схемами**:
где-то `z.object({code})`, где-то `z.object({code, message})`. То есть OpenAPI
описывал ошибку не тем типом, который реально приходил.

Заменено на `ProblemSchema` — единственный тип ошибки.

## Что теперь закрывает `proto:arch`

| Правило | Как проверяется |
|---|---|
| ≤ 200 строк в файле | подсчёт строк |
| ≤ 5 экспортов | подсчёт `export function/const/class/type` |
| ≤ 3 уровней вложенности | разбор текста: строки, комментарии и шаблоны вырезаются, считаются блоки **управления**, а не скобки объектных литералов |
| нет `init()` | поиск объявления функции |

Первая версия считала вложенность по отступам и находила «16 уровней» внутри
SQL-шаблона. **Гейт, который врёт, хуже отсутствующего** — его перестают читать.
