# Этап 5 — вывод 1С и OData: закрыт

**Дата:** 13.11.2026 · **Задание:** [prototype-spec.md](../../prototype-spec.md) §6, §10

## Почему этот этап короче остальных

Этап 5 в задании — «вывод 1С и OData». В прототипе **выводить нечего**: он построен
с нуля в отдельной папке и никогда их не содержал. Этап закрыт по построению, и это
нужно проверить, а не предположить.

## Проверки

| Что проверялось | Как | Результат |
|---|---|---|
| Ни одного столбца 1С | `information_schema.columns` по всей схеме | **0** столбцов `onec_*`, `extra`, `import_batch_id`, `predefined`, `is_folder`, `ext_code`, `link_key`, `sort_order`, `cell_legacy`, `manual_*` |
| Нет клиента 1С | поиск в `src/` | нет |
| Нет OData | поиск в `src/` | нет |
| Задание «В работе» работает без 1С | `POST /sales/jobs` | выполняется целиком в приложении: строка → «Заказан», создаётся заказ поставщику |
| Данные при старте | `seed/templates/refs.sql` | справочники версионируются вместе с миграциями |
| Данные для тестов | `seed/processes/*.sql` | по файлу на процесс, фиксированные UUID |

**Удалённые столбцы (11):** `onec_record_id`, `onec_version`, `onec_key`, `cell_legacy`,
`import_batch_id`, `manual_edit`, `manual_batch`, `manual_split_by_batch`, `link_key`,
`sort_order`, `extra`.

`extra` (jsonb) удалён намеренно: он противоречит правилу «явные типы» из §12 —
в него сваливали всё, для чего не хватило колонки.

## Единственные входы данных

1. `seed/templates/refs.sql` — справочники при старте;
2. `POST /imports` — оператор вводит лист клиента (N1 → M1);
3. API — всё остальное.

1С в этом списке нет, и это то, что делает прототип автономным: он запускается
на пустой машине, без публикаций и без обмена.
