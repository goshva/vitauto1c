# Проблемы после подстановки общего помощника

Замер: **924 теста проходят, 9 падают.** У всех девяти ОДНА причина, и это важно: не девять
разных поломок, а одна, проявившаяся девять раз.

## Причина

Тесты подставляют роль **заголовком `X-Role`**:

```ts
const as = (role: Role) => ({ 'x-role': role });
await request(url, { headers: as('storekeeper') });
```

Но роль **больше не берётся из заголовка**. Это записано в `src/auth.ts` прямым текстом:

> БЫЛО: роль предъявлялась заголовком `X-Role`, и это было записано как ограничение
> прототипа — «подделать тривиально, защитой не притворяется».
> СТАЛО: учётные записи и вход с паролем. Роль приходит из ПОДПИСАННОЙ сессии.

Общий помощник добавил к таким запросам **сессию администратора** — и роль стала `admin`,
хотя тест просил кладовщика. Отсюда два вида падений:

| Что проверял тест | Что получил | Почему |
|---|---|---|
| кладовщику отказано (403) | **200** | вошёл администратор, ему можно |
| кладовщику нет `costPrice` | **`costPrice` есть** | администратор видит всё |

## Почему это НЕ поломка, а находка

**Тесты были правы, а способ подстановки роли — устаревший.** Заголовок, который клиент
ставит сам, не может определять права: это не проверка прав, а её видимость. Тесты
пользовались им потому, что иначе роль не подставить, — а теперь есть сессия.

То есть эти девять падений показывают **настоящее состояние**: право определяется сессией, и
подделать его заголовком нельзя. Это ровно то, чего хочет заказчик.

## Что чинить

Заменить заголовок на сессию — по одному месту в каждом файле:

```ts
// было
const as = (role: Role) => ({ 'x-role': role });
await request(url, { headers: as(role) });

// стало
const as = () => ({ accept: 'application/json' });
await request(url, { headers: as() }, role);
```

Третий аргумент помощника — роль, и он ставит подписанную куку. Заголовок убирается совсем:
оставлять его рядом с сессией значило бы показывать, будто он на что-то влияет.

## Что это меняет в плане

Помощник оказался не только заменой вызова: он **вскрыл шесть файлов, которые проверяли права
через заголовок**. Их правка — часть шага 2, и она делает проверки прав честными: теперь они
проверяют то, чем права действительно определяются.
