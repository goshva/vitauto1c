# Разбор прототипа: архитектура, отказоустойчивость, гибкость, «AI-first»

**Дата:** 18.11.2026 · **Предмет:** `proto/` · **БД:** `vitauto_proto` (127.0.0.1:5434) · **Порт:** 18190

Разбор сделан по коду и по **живым проверкам**, а не по документам репозитория: часть
документов устарела (см. §3.3). Каждое утверждение ниже либо имеет ссылку `файл:строка`,
либо помечено как непроверенное.

Что запускалось при разборе:

|---|---|---|
| Архитектурные гейты | `bun run arch` | **187 файлов, 0 нарушений** |
| Типы | `bun run typecheck` | **exit 0**, ошибок нет |

чтением кода.

## 1. Что это и в каком объёме

Прототип АРМ ВИТАВТО: **Bun + Hono + Drizzle + Zod + HTMX + Playwright**, PostgreSQL 18.
Живёт в монорепозитории `vitauto1c` рядом с Go-API и PWA, но изолирован: своя база
`vitauto_proto`, свой порт 18190, ручной стенд `vitauto_app`/18180 не трогается
(`.env.example`, `db/reset.ts:22-29`).

| Метрика | Значение |
|---|---|
| `.ts` в `src/` | **133 файла**, 13 183 строки (`Get-Content \| Measure-Object -Line`) |
| Крупнейший файл | 182 строки (`src/views/print.ts`) |
| Миграции | 30 файлов, в базе применено 32 записи журнала |
| Схема БД | 16 файлов `db/schema/*.ts`, 37 таблиц + 3 представления |
| `line` / `line_view` | 44 / 50 столбцов (в legacy-карте было 82) |
| API | 60 путей / 76 операций в `openapi.json`; 66 регистраций в 62 под-приложениях |
| Тесты | 61 файл, ≈928 объявлений `test(`; e2e — 11 спеков, 69 объявлений |
| Витрина в БД | 62 строки, 54 заказа поставщику, 48 приёмок, 14 отгрузок, 35 движений, 224 записи аудита |

Задание прототипа написано «под AI-агента» (`../prototype-spec.md:5`, §9 — «главный раздел
для агента», метрика «итераций агента в день ≥ 800»). Это ключ к трактовке «AI-first»:
система делается так, чтобы её **собирал и водил агент**, а не чтобы в ней был ИИ.

в `src/db.ts:8-9` и `src/server.ts:81`, поэтому без `.env` запуск тоже состоится — но
`db:reset` откажется работать, если в URL нет `vitauto_proto` (`db/reset.ts:22-29`).

### 2.3. Три помехи, которые сломают запуск «как есть»

1. **Порт 18190 занят.** На момент разбора там работал ранее запущенный экземпляр
   (PID 5100, песочнице не виден). Свежий `bun run dev` падает `EADDRINUSE`
   (`src/server.ts:80-86`). `stop-dev.ps1` в корне монорепозитория прототип **не
   останавливает** — он про Go-API и PWA.
2. **Автозапуск кластера 5434 не подтверждён.** Рядом слушает второй кластер на 5433
   (служба `postgresql-1c-18`), а у 5434 конфиг `D:/vitauto_app/pgdata/postgresql.conf`.
   После перезагрузки его, возможно, придётся поднимать `pg_ctl`.
3. **`Taskfile.yml` — в корне монорепозитория**, не в `proto/` (`../Taskfile.yml:87-167`),
   а в CI **нет ни одной job для `proto/`** (`../.github/workflows/ci.yml`): все гейты
   прототипа ручные.

Мелочи, о которых забывают: `SESSION_SECRET` не задан → генерируется на процесс, после
рестарта **все сессии умирают** (`src/session.ts:23-24`); миграции только вверх, единственный
«откат» — `db:reset`.

## 3. Архитектура

### 3.1. Слои выдержаны

`db/schema` (Drizzle — единственный источник схемы, `drizzle.config.ts:3`) → `domain/*`
(чистые правила: `src/domain/status.ts`, `transition.ts`, `columns.ts`, `access.ts`) →
модули-маршруты `src/*.ts` → `views/*` (серверный HTML) → `routes.ts` (только порядок
монтирования) → `server.ts` (только сборка: middleware, обработчик ошибок, статика).

Глобальных переменных нет, `init()` нет — и это **проверяется машиной**, а не декларацией:
`scripts/arch.ts:20` держит ≤200 строк, ≤5 экспортов, вложенность, запрет `init()` и
запрет U+FFFD в комментариях. Сейчас — 0 нарушений на 187 файлах.

Сильные стороны, подтверждённые кодом:

| Что | Где |
|---|---|
| Один тип ошибки на всё API (RFC 9457: code/status/message/field/traceId) | `src/problem.ts:11-33` |
| Ошибки валидации Zod приведены к тому же формату | `src/api.ts:34-41` |
| Одна таблица переходов вместо четырёх копий legacy; из неё строятся кнопки | `src/domain/transition.ts:22-54` |
| Один URL — два представления: браузеру HTML, агенту JSON | `src/negotiate.ts:15-18` |
| Сквозной `X-Request-ID` | `src/request-id.ts:7-14` |
| `Idempotency-Key` с реплеем ответа | `src/idempotency.ts:19-57` |
| Закрытые колонки удаляются из ответа, а не обнуляются | `src/domain/columns.ts:47-55` |
| Инъекций SQL не найдено: всё параметризовано, включая `${column}` из белого списка | `src/lines-fields.ts:187`, `src/lines-bulk.ts:101` |

### 3.2. Слабые места

- **Порядок маршрутов — часть поведения**, и это уже трижды ломало проект: комментарии в
  `src/routes.ts:78-138` фиксируют потерянные `/fleet/:id`, `/lines/summary` и
  `/print/work_order`. Один список из 66 `app.route()` — хрупкая точка.
- **Правило ≤200 строк дробит модули**: 27 из 43 файлов с записью в БД — «огрызки» логики,
  между которыми нет транзакционной границы (см. §4). Гейт защищает читаемость, но не
  целостность операций.
- **Слоя доступа к данным нет**: `pool.query` вызывается напрямую в 68 файлах (~200 вызовов).
  Это осознанный «тонкий» дизайн, но транзакционные границы приходится собирать вручную в
  каждом потоке — и в 27 файлах с записью они не собраны.
- **Гейты проверяют форму, а не свойства**: `scripts/verify-gates.ts` печатает числа;
  ошибки типов (`:63`) на код возврата **не влияют** (падение `arch` на `:64` — влияет,
  оно не перехвачено). Зелёный гейт ≠ выполненное свойство.

## 4. Отказоустойчивость

### 4.1. Что сделано хорошо

- Транзакции реально есть в 19 файлах: приёмки, отгрузки, возвраты, заказы поставщику,
  ремонт, склад, импорт (`src/receipts-flow.ts`, `shipments-flow.ts`, `returns-flow.ts`,
  `supplier-orders-flow.ts`, `work-orders-*.ts`, `stock.ts`, `imports.ts`, `import-paste.ts`).
- Копии снимаются вместе с описью содержимого и **проверяются восстановлением в отдельную
  базу** — это самая доказанная часть (`tests/integration/backup.test.ts:176-271`).
- Пропущенное задание догоняется по «сколько прошло», а не по календарю
  (`src/jobs-run.ts:152`), просрочка видна отдельным полем (`:155`), сбой не отключает
  задание и даёт нарастающую задержку повтора (`:136-138`).
- `dbPing` никогда не бросает: `/health` обязан ответить и сказать правду (`src/db.ts:17-29`).

## 5. Гибкость

- **Слоя конфигурации нет**: `src/env.ts` — только типы Hono; 56 обращений к `process.env`
  в 20+ файлах; дефолты зашиты (порт 18190, `hostname: '127.0.0.1'`, DSN, `PGPASSWORD`),
  валидации нет — `PORT=abc` даст `NaN` и падение `Bun.serve`, а не внятный отказ.
- **Колонки и статусы — код, процессы — данные, но вне репозитория**: `src/domain/columns.ts:24-27`
  (закрытые поля — литеральный объект), `STATUSES`/`TRANSITIONS` — код; карта процессов
  читается из `../../docs/migration/ddd/domain-model.json` (`scripts/process-map.ts:12`),
  то есть **вне `proto/`**, плюс второй независимый список 11 процессов в
  `scripts/gen-process-seeds.ts`. Новый процесс = правка внешнего JSON + генератора +
  перегенерация четырёх сидов.
- **Дрейф уже случился** (§3.3): статусы в трёх местах, три словаря ролей
  (`src/domain/roles.ts`, `src/domain/access.ts`, `src/domain/process-map.ts`), демо-учётки
  продублированы в `src/login-ui.ts:30-35` и сиде.
- **Мультитенантности, i18n, часового пояса нет**: `organization_id` в схеме есть, фильтра
  по нему нет ни в одном запросе; `₽` и `'шт'` — литералы в разметке; даты —
  `toLocaleDateString('ru-RU')` (`src/views/print.ts:79`), зависят от TZ машины.
- **Переносимость ограничена**: абсолютные пути к `psql` и `bun` (`scripts/verify-gates.ts:10-14`,
  `scripts/coverage.ts:16-23`), два захардкоженных DSN, включая рабочую `vitauto_app`
  (`scripts/migrate-from-1c.ts:24-25`), Dockerfile/compose нет.

## 6. «AI-first»: что есть и чего нет

### 6.1. Есть (не маркетинг)

1. Один тип ошибки + `traceId`, равный `X-Request-ID` (`src/problem.ts`, `src/request-id.ts`).
2. `Idempotency-Key` с реплеем ответа (`src/idempotency.ts`).
3. `If-Match`/`version_conflict` — на двух маршрутах (`src/lines-fields.ts`, `src/orders-edit.ts`).
4. Один URL — два представления: HTML браузеру, JSON агенту (`src/negotiate.ts`).
5. `openapi.json`, **сгенерированный из Zod**, а не написанный руками (`scripts/openapi.ts`).
6. Отказы называют допустимые значения: статусы (`src/lines.ts:85-86`), роли
   (`src/domain/access.ts`), переходы (`src/domain/transition.ts:62-76`).
7. Детерминированные сиды, фиксированные UUID, `resetTo` для изоляции (`db/seed.ts:88-99`).

### 6.2. Нет

1. **Ни одного канала обнаружения**: нет `AGENTS.md`, `README.md`, `llms.txt`, MCP-сервера,
   tool-схем. Поиск `mcp|llm|openai` по репозиторию — 0 совпадений. Слово «агент»
   встречается ~12 раз **только в комментариях** как замысел.
2. **OpenAPI не публикуется по HTTP** (маршрута нет) и отстал от кода на 11 путей.
3. **Нет GET допустимых переходов**: `allowedFrom()` (`src/domain/transition.ts:53`) не
   экспонирован; узнать «что можно из `reserve`» можно лишь из TS-исходника или из текста
   409, где переходы названы **русскими подписями кнопок**, а не кодами.
4. **Нет токен-аутентификации** (только cookie-сессия), при этом аноним = admin, CSRF-токена
   нет, `Vary` при двух представлениях нет.
5. **HTML-only экраны**: `/processes`, `/documents/*`, `/jobs`, `/audit`, `/reports` — агенту
   как данные недоступны; пакетные операции — только через глобальную отметку строк.
6. **Нет dry-run** и самопроверки артефактов (OpenAPI, сиды, docs расходятся с кодом — и это
   не ловится).

### 6.3. Вердикт

Это аккуратный **API-first монолит** с хорошей гигиеной ошибок и сидов, пригодный для
агента-скрипта, который читает исходники. Как **AI-first** — заявка не выполнена: нет
ни канала обнаружения, ни машинного описания переходов, ни токенов, а доступ по умолчанию —
администратор без входа.

## 7. Приоритеты

| Приоритет | Действие |
|---|---|
| **P0** | Подключить флаг `PROTO_TEST_HOOKS` или снять `/__test__/seed`; убрать `?? 'admin'` и закрыть данные прослойкой; уникальный индекс идемпотентности + `and not posted` в проведении |
| **P1** | Транзакции в переходах/шагах/массовых правках; аудит в той же транзакции; `and version = $n`; `statement_timeout`; SIGTERM + `pool.end()`; `/ready`; блокировка задания |
| **P2** | Гейт «артефакты не разошлись»; падающий `verify-gates` по типам; job для `proto/` в CI; `/openapi.json` и `GET /lines/{id}/transitions`; `AGENTS.md` |

Пошаговый разбор P0 с критериями приёмки — в `docs/p0-checklist.md`.
