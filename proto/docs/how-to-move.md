# Как провести заказ по процессу через интерфейс

Инструкция для оператора. Описывает только то, что есть на экране, и в том порядке,
в каком это делается руками.

**Адрес АРМ:** `http://127.0.0.1:18190` (после `bun run dev` в каталоге `proto`).

---

## Что такое «узел» и «сдвинуть заказ»

Заказ в АРМ — это **строка** (`line`). У неё есть состояние: «Новый», «Зарезервирован»,
«Заказан» и так далее. «Сдвинуть на следующий узел» — перевести строку в следующее
состояние процесса.

Состояния и их названия для оператора лежат в одном месте, и на экране вы видите
русское слово, а не машинный код:

| Код | На экране |
|---|---|
| `new` | Новый |
| `reserve` | Резерв |
| `ordered` | Заказан |
| `paid` | Оплачен |
| `in_transit` | В пути |
| `acceptance` | Приёмка |
| `to_stock` | На склад |
| `assembly` | Комплектация |
| `ready_to_ship` | Собрано |
| `shipped` | Отгружен |
| `closed` | Закрыт |
| `return` | Возврат |
| `cancelled` | Отменён |
| `refused` | Отказался |

**Важно:** кнопки строятся из той же таблицы переходов, что и проверка на сервере.
Кнопка не может появиться там, где переход запрещён, и наоборот. Если кнопки нет —
переход из текущего состояния невозможен, и это не ошибка экрана.

---

## Шаг 1. Открыть список

Боковая панель → **Строки**. Адрес: `/lines`.

Вы увидите таблицу со всеми строками по всем заказам. Колонки: номер, состояние,
«Срочно», заказ клиента, наименование, артикул, количество, остаток, резерв,
заказчик, цена, сумма, комментарий.

---

## Шаг 2. Отметить строки

Поставьте **флажок** в первой колонке у нужной строки (или у нескольких).

Как только отметите, над таблицей появится **панель действий**:

```
[2]  Отмечено: 2 · статус «Новый»
     [Зарезервировать] [Отменить]
     Цепочка: [В работе (M4)] [Оплачен] [В пути] [Приёмка] [На склад] [Комплектация] [Собрано]
              Зона: [Малый склад ▾] [Переместить]
              Ячейка: [A-01 ▾] [Разместить]
     Печать: [Сборочный лист] [Отгрузочная ведомость] [Корректировка ведомости]
```

Кнопки **не перезагружают страницу** — список обновляется на месте.

**Если отметить строки с РАЗНЫМИ состояниями**, покажутся только те кнопки, которые
работают для всех сразу, а ниже появится строка «Недоступно для части строк: …».
Так сделано намеренно: иначе вы нажали бы кнопку и получили «обработано 0».

---

## Шаг 3. Двигать по узлам

Дальше — тремя способами. Все они на одной панели.

### Способ А. Кнопки перехода

Это переходы состояния: `[Зарезервировать]`, `[На комплектацию]`, `[Собрано]`,
`[Самовывоз]`, `[Принять по УПД]`, `[Возврат]`, `[Закрыть]`, `[Отменить]`,
`[Клиент отказался]`.

Что доступно — зависит от текущего состояния. Например, у «Нового» есть только
`[Зарезервировать]` и `[Отменить]`.

**Как нажать:** отметить строку → нажать нужную кнопку → список обновится.

### Способ Б. Цепочка (задание и канбан снабжения)

| Кнопка | Что делает | Из каких состояний |
|---|---|---|
| **В работе (M4)** | Задание: строка уходит в заказ | Новый, В работе, Собрано |
| **Оплачен (M7)** | Отметка оплаты поставщику | Заказан |
| **В пути (P2)** | Товар едет | Оплачен |
| **Приёмка (K1)** | Товар пришёл | В пути |
| **На склад (K2)** | Размещён | Приёмка |
| **Комплектация (M9)** | Собирается | На склад, Резерв |
| **Собрано (K3)** | Готов к выдаче | Комплектация |

Нажимайте **по порядку**: каждая кнопка работает только из своего состояния.

### Способ В. Зона и ячейка

Это не смена состояния, а **перемещение** — куда физически положили товар.

- **Зона** — выберите помещение и нажмите `[Переместить]`. Ячейку система подберёт
  сама: оператор выбирает помещение («после ремонта — на склад», «брак — поставщику»),
  а не полку.
- **Ячейка** — выберите конкретную ячейку и нажмите `[Разместить]`.

Перемещение **не меняет количество** на складе. Количество меняют приёмка, отгрузка
и ручное движение.

## Полная цепочка: от заявки до закрытия

Так проходит обычный заказ. Каждый шаг — нажатие одной кнопки.

| # | Что делаете | Кнопка | Состояние после |
|---|---|---|---|
| 1 | Загрузить заявку | «Загрузить лист клиента» → **Создать заказ** | Новый |
| 2 | Взять в работу | **В работе (M4)** | Заказан |
| 3 | Отметить оплату | **Оплачен (M7)** | Оплачен |
| 4 | Товар поехал | **В пути (P2)** | В пути |
| 5 | Товар пришёл | **Приёмка (K1)** | Приёмка |
| 6 | Разместить | **На склад (K2)** | На склад |
| 7 | Собрать | **Комплектация (M9)** | Комплектация |
| 8 | Сборка окончена | **Собрано (K3)** | Собрано |
| 9 | Закрыть | **Закрыть** | Закрыт |

Заявка заводится через свёрнутый блок **«Загрузить лист клиента (N1 → M1)»** над
таблицей: разверните его, заполните наименование (обязательно), артикул, количество,
единицу и номер заказа клиента, нажмите **«Создать заказ»**.

**Шаг 9 требует галки.** Закрытие отгруженной строки проходит только если в строке
отмечено «Документ подписан оригинал». Иначе АРМ ответит причиной, а не промолчит.

## Отказ клиента

Клиент может отказаться. Отдельного документа отмены **нет** — состояние ставится
прямо строке:

- **Отменить** — клиент отказался до выдачи. Доступно из: Новый, В работе, Заказан,
  Оплачен, В пути, Приёмка, На склад, Резерв, Комплектация.
- **Клиент отказался** — отказался при получении. Доступно из: Собрано, Отгружен.

Разница важна складу: в первом случае товар ещё не уехал, во втором возвращается.

---

## Если кнопки нет

Проверьте по порядку:

1. **Строка отмечена?** Без флажка панель действий пустая — это самая частая причина.
2. **Какое состояние у строки?** Смотрите колонку «Статус». Кнопка есть не из любого
   состояния.
3. **Отмечено несколько строк с разными состояниями?** Показываются только общие
   кнопки. Ниже будет написано, что именно недоступно.
4. **Хотите закрыть отгруженную?** Нужна галка «Документ подписан оригинал».

Отказ всегда приходит **с причиной** и названием состояния словами, например:
«Из состояния „Отменён“ переходов нет». Молчаливого «не сработало» в АРМ нет.

## Карта процессов

Боковая панель → **Карта процессов** (`/processes`).

Схема показывает все 11 процессов по шагам. Рядом с каждым шагом стоит **число —
сколько строк сейчас в этом состоянии**. Синее — есть строки, серое — ни одной.

**Нажмите на число** — откроется список этих самых строк. Так от схемы сразу
переходят к делу: увидели пустой узел, нажали, посмотрели.

Полный список процессов:

| Процесс | Что описывает |
|---|---|
| `happy` | Основной: закупка → отгрузка |
| `stock` | Со склада (резерв) |
| `mixed_order` | Смешанный заказ: часть со склада, часть под заказ |
| `delivery_split` | Самовывоз у поставщика |
| `virtual_buy` | Виртуальный закуп |
| `defect` | Контроль комплектации |
| `cancel_supplier` | Отмена заказа у поставщика |
| `return` | Возврат от клиента |
| `return_mgr` | Возврат поставщику |
| `return_internal` | Отказ клиента при получении |
| `car_repair_in` | Поступление машины в ремонт |

## Посмотреть демонстрацию целиком

Чтобы на каждом узле каждого процесса была строка:

```powershell
cd proto
bun run db:seed --showcase   # 61 строка: по одной на каждый узел каждого процесса
bun run dev
```

Откройте **Карта процессов** — у каждого шага будет число больше нуля, и по нажатию
на него откроется список. Это и есть проверка, что демонстрировать есть что.

**Проверено автоматически:** 10 тестов в `tests/integration/ui-walkthrough.test.ts`
проходят цепочку «Новый → Закрыт» **только кнопками интерфейса** и проверяют, что на
каждом узле каждого из 11 процессов есть чем двигать дальше.
