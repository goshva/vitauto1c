# Что открыто без входа: разбор цифр

Замер сделан `bun run scripts/access-matrix.ts` и разовым подсчётом вызовов в тестах.
Ниже — что каждая цифра значит и что с ней делать.

## Два разных вопроса

Я измерял ДВЕ разные вещи, и путать их нельзя:

| Что | Смысл | Зачем |
|---|---|---|
| **Маршруты без охраны** | сколько адресов отвечают тому, кто НЕ вошёл | это и есть дыра |
| **Вызовы в тестах без сессии** | сколько тестов ходят без входа | это ЦЕНА закрытия |

Первое — проблема. Второе — работа, которую придётся сделать, чтобы проблему закрыть.

## Цифры

**Маршруты:** всего GET-адресов **68**. Из них **49 отдают данные без входа**, 19 закрыты или
не найдены по этому методу.

**Тесты:** всего вызовов `app.request` **147**. С сессией **24**, **без сессии 123** — в
**44 файлах**.

## 49 открытых адресов — они НЕ одинаковые

Это главное, чего не видно в сыром списке. Три разные группы, и решение по ним разное:

### Группа 1. Служебные — так и должно быть (3 адреса)

```
/health        — проверка живости: по нему балансировщик решает, жив ли сервер
/login         — страница входа: иначе войти некуда
/__test__/seed — сид для проверок, живёт только при PROTO_TEST_HOOKS=1
```

**Оставить открытыми.** Закрыть `/health` значит сломать проверку живости; закрыть `/login` —
сделать вход невозможным.

### Группа 2. Страницы (12 адресов)

```
/  /lines  /supply  /documents/returns  /fleet  /stock
/unidentified  /invoices  /processes  /reports  /audit  /jobs
```

**Решение заказчика: экраны показываем все.** То есть роль НЕ мешает открыть раздел —
ограничивается только видимость столбцов.

НО «показываем все» — это про РОЛИ, а не про вход. Без сессии роль неизвестна, и показывать
нечего: страница должна вести на вход.

### Группа 3. Данные (34 адреса)

Всё остальное: `/refs/*` (8), `/ui/*` (6), `/lines/export`, `/lines/summary`,
`/reports/profitability`, `/reports/stuck`, `/orders`, `/receipts`, `/shipments`,
`/returns`, `/returns/find`, `/stock/balance`, `/supplier-orders`, `/suppliers`,
`/work-orders`, `/zones`, `/employees`, `/maintenance`, `/fleet/maintenance`,
`/lines/{id}/history`.

**Вот это и закрывается.** Здесь данные отдаются напрямую.

## Особый случай: `/lines` — и страница, и API

Один адрес отдаёт РАЗНОЕ по заголовку `Accept`: браузеру — страницу, агенту — JSON. Это
называется согласованием представления, и оно уже работает.

Значит «закрыть данные» для него означает: **JSON закрыт, страница ведёт на вход**. Одно
правило, разное поведение — по тому же признаку, по которому выбирается представление.

## Цена закрытия: 123 вызова в тестах

Это не мелочь, и её надо назвать прямо. **123 вызова в 44 файлах** ходят в приложение без
сессии. После закрытия каждый такой вызов получит 401 и тест упадёт.

Причина в том, что общего помощника для тестов нет: каждый файл сам зовёт `app.request`.
Лечится это одним общим помощником, который подставляет сессию, — и тогда правка касается
одного места, а не 44 файлов.

## План закрытия

### Шаг 1. Одна проверка на всё приложение

Прослойка: нет сессии — HTML ведёт на `/login`, JSON отвечает 401. Исключения: `/health`,
`/login`, `/logout`, `/static/*`, `/__test__/seed` (под тестовым флагом).

**Почему прослойка, а не проверка в каждом обработчике.** Их 68. Проверка в каждом — 68
поводов забыть; прослойка — одно место, и новый маршрут закрыт по умолчанию.

### Шаг 2. Общий помощник для тестов

Функция, которая делает запрос с сессией нужной роли. Тогда 123 вызова правятся заменой
`app.request(` на `asRole(`, а не вручную.

**Тесты, которые ПРОВЕРЯЮТ закрытость, остаются без сессии** — иначе проверять будет нечего.

### Шаг 3. Закрыть цену продажи кладовщику

Решение заказчика: **закрыть**. Добавляется в `columns.ts` к уже закрытым полям, и таблица
перестаёт показывать колонки «Цена» и «Сумма» — механизм для этого уже сделан.

### Шаг 4. Проверки

- без сессии: страница ведёт на вход, данные отвечают 401;
- с сессией: всё как было;
- `/health` и `/login` открыты без входа;
- кладовщику нет колонок «Цена» и «Сумма», менеджеру есть;
- число колонок в шапке и в строке совпадает при любой роли.

## Чего этот разбор НЕ решает

**Какие столбцы кому видны** — это отдельный вопрос, и он в `docs/visibility-plan.md`. Там же
противоречие между эталоном `index.html` (кладовщик видит цены) и ФТ v2 п. 5 (не видит).
Заказчик решил: **закрыть**.
