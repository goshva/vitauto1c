# Прототип АРМ: инструкция оператора

**Задание:** [prototype-spec.md](../prototype-spec.md) · **Порты:** прототип 18190, БД `vitauto_proto`

Инструкция описывает **прототип**, а не легаси-приложение. Легаси-инструкция —
[manual.md](../manual.md) в корне; она остаётся для ручного стенда на 18180.

## 1. Запуск

```powershell
task proto:reset          # снести схему → миграции → справочники
task proto:seed PROCESS=happy   # состояние одного процесса
task proto:dev            # http://127.0.0.1:18190
```

Администратор один и делает всё: прав и ролей в прототипе нет (задание §5).

### Витрина: все этапы всех процессов сразу

```powershell
task proto:seed:showcase   # 61 строка — по одной на каждую пару «процесс × состояние»
```

Обычные сиды дают один-два процесса, и карта процессов «живая» лишь на части шагов.
Витрина заполняет **все 11 состояний** плюс необходимые документы: 61 заказ,
48 приёмок, 14 отгрузок, 54 заказа поставщику, 4 возврата, 35 движений склада.

Запускается **отдельно** от `--all`: 61 строка и десятки документов сделали бы
состояние e2e непредсказуемым — тесты рассчитывают на состояние одного процесса.
`--all` при этом сначала **очищает** транзакции, поэтому после витрины достаточно
выполнить `--all`, чтобы вернуться к состоянию для тестов.

## 2. Экраны

| Экран | Адрес | Для чего |
|---|---|---|
| Строки | `/lines` | заявка → резерв → комплектация → отгрузка → закрытие |
| Закупки | `/lines?view=purchases` | заказы поставщику |
| Снабжение | `/supply` | контроль оплаты, «в пути», приёмка, склад |
| Документы | `/documents/returns` | возвраты, отгрузки, заказы поставщику, заказ-наряды |
| Неопознанные | `/unidentified` | K8, A1 — розыск и привязка номенклатуры |
| Карта процессов | `/processes` | 11 процессов, 121 шаг, статистика по состояниям |

Печатные формы: сборочный лист, отгрузочная ведомость, корректировка ведомости —
ссылки в панели действий, открываются в новой вкладке.

## 3. Три места, где нажимают кнопки

| Где | Что там |
|---|---|
| **Строка списка** | флажок отметки; состояние словами («Оформлен», а не `new`) |
| **Панель действий** | переходы процесса, кнопки цепочки, печать |
| **Экран документов** | действия над возвратом, отгрузкой, заказом, нарядом |

**Базовый приём:** отметить строки → нажать действие. Из смешанных состояний
показывается **пересечение** допустимых переходов и подсказка, что недоступно.

После действия **отметки снимаются** — это не дефект: следующее действие не должно
задевать те же строки незаметно.

## 4. Процессы

Одиннадцать процессов, у каждого своё начальное состояние — **четыре начинаются
не с «Нового»**:

| Процесс | Начало | Чем отличается |
|---|---|---|
| `happy` | Новый | остатка нет — идёт через закупку |
| `stock` | Новый | остаток есть — идёт через резерв |
| `mixed_order` | Новый | две строки: одна со склада, одна в закупку |
| `delivery_split` | Новый | самовывоз: комплектация не нужна |
| `virtual_buy` | Новый | короткий путь без комплектации |
| `defect` | **Комплектация** | начинается с контроля, а не с заявки |
| `cancel_supplier` | **Заказан** | отмена возвращает строку в «Новый» |
| `return` | **Отгружен** | сначала документ возврата, он и переводит строку |
| `return_mgr` | **Возврат** | возврат уже оформлен |
| `return_internal` | **Собрано** | клиент отказался при получении |
| `car_repair_in` | Новый | привязан автомобиль и заказ-наряд |

## 5. Особые правила

| Правило | Как проявляется |
|---|---|
| Закрытие отгруженной строки | требует галки «Документ подписан оригинал» (C22) |
| Переход из недопустимого состояния | отказ **называет** доступные переходы, а не молчит |
| Неизвестный статус в фильтре | 400 со списком допустимых (C18) |
| Проведённую приёмку/отгрузку/наряд | нельзя удалить — только сторнировать |
| Перемещение между зонами | меняет место, а не количество: остаток не меняется |
| Неопознанная позиция | это строка **без номенклатуры**, а не отдельная сущность |

## 6. Связь с автотестами

| Что проверяется | Где |
|---|---|
| карта 82 столбцов и разрез `line` | `tests/unit/schema.test.ts` |
| представления считают верно | `tests/integration/views.test.ts` |
| один тип ошибки, включая валидацию | `tests/unit/problem.test.ts` |
| каждый процесс начинается в объявленном состоянии | `tests/integration/processes.test.ts` |
| API: строки, документы, справочники, склад | `tests/integration/*.test.ts` |
| экран строк и переходы в браузере | `e2e/happy-chain.spec.ts` |
| печатные формы и экран снабжения | `e2e/print-and-supply.spec.ts` |
| экран документов | `e2e/documents.spec.ts` |
| **все 11 процессов через HTTP** | `e2e/processes.spec.ts` |

### Что НЕ покрыто автотестами

**Пусто.** Каждый шаг инструкции покрыт: либо интеграционным тестом по API, либо
сквозным прогоном в браузере.

**Выпадает по решению задания §5** (не «не покрыто», а вне контура прототипа):

| Что | Почему |
|---|---|
| «Одобрить» / «Отклонить» (`/access-requests`) | права и роли выброшены; возвращаются **после** прототипа как «Test before Develop» |
