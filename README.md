# Витавто 1С

## Установка и запуск (1С:Предприятие + PostgreSQL + технологический журнал)

Скрипт [install-1c.ps1](install-1c.ps1) полностью автоматизирует развёртывание на чистой Windows:

1. удаляет прошлую установку;
2. скачивает с Яндекс.Диска и распаковывает платформу **1С:Предприятие 8.3.27.2342**, **PostgreSQL 15.13‑1.1C** и файловую базу **«Автосервис»**;
3. ставит PostgreSQL (кластер в UTF‑8, русская локаль), создаёт службу;
4. ставит платформу 1С и службу сервера;
5. настраивает **технологический журнал** (`logcfg.xml`) и перезапускает агент;
6. мигрирует файловую базу в PostgreSQL и подключает расширение конфигурации (`.cfe`);
7. проверяет подключение и появление файлов ТЖ.

### Требования

- Windows 10/11, запуск **от администратора** (скрипт сам повышает права).
- Свободное место: **~10 ГБ на SSD** (база PostgreSQL, программы) и **~10 ГБ на HDD** (архивы, распаковка). Скрипт проверяет место заранее.
- Пароль суперпользователя PostgreSQL — **только ASCII** (латиница, цифры, спецсимволы). Кириллица не пройдёт: psql и 1С используют разные кодировки.
- **Комьюнити‑лицензия 1С** (developer.1c.ru, платформа ≥ 8.3.23): без активации конфигуратор не откроет базу. Активируется вручную: диалог «Получение лицензии» → «Активировать комьюнити‑лицензию». Скрипт лицензию не ставит.
- Файлы, которых **нет в репозитории** (см. `.gitignore`) и которые нужны рядом со скриптом:
  - расширение `.cfe` — по умолчанию ищется `АРМЗакупокИПродаж_v1.cfe`; другое имя/путь: `-ExtensionFile "…\файл.cfe"`; без расширения: `-ExtensionFile ''`;
  - дистрибутивы 1С/PostgreSQL/базы скачиваются автоматически с Яндекс.Диска.

### Запуск

```powershell
# из папки репозитория, PowerShell от администратора:
.\install-1c.ps1 -Force -DeleteArchives -BaseDir D:\1c
```

- `-BaseDir D:\1c` — куда класть архивы, распаковку и логи (диск без требований к скорости, напр. HDD). База PostgreSQL и программы всегда на системном диске (SSD).
- `-DeleteArchives` — удалять архивы после распаковки.
- Пароль PostgreSQL спросит скрытым вводом (или задайте `-PgPassword`).
- Пользователь базы 1С подбирается автоматически (`Админ`/`Администратор` без пароля); иначе `-IbUser "Имя"`.

Полезные ключи: `-NoTrace` (без ТЖ), `-TechLogDir D:\1c\tj`, `-TechLogThresholdMs 200` (события DBMS дольше N мс), `-LogcfgPath`, `-ExtensionFile` (путь к `.cfe` или `''`), `-SkipSpaceCheck`, `-PgPort 5433`.

### Технологический журнал (трассировка)

Трассировка запросов к СУБД — штатными средствами платформы 1С, без Redis и коллекторов.

- Конфиг: `C:\Program Files\1cv8\conf\logcfg.xml` (общий для серверных процессов; параметр `-LogcfgPath`).
- Файлы журнала: `-TechLogDir` (по умолчанию `D:\1c\tj`, лучше HDD, не SSD с базой).
- По умолчанию пишутся события **DBMS** длительностью ≥ **200 мс** (`-TechLogThresholdMs`); хранение истории — 24 часа.
- После записи `logcfg` скрипт перезапускает агент сервера 1С (шаг до создания базы).
- В конце установки проверяет появление новых файлов в каталоге ТЖ: при успехе — OK, если файлов нет — предупреждение (установку базы не считает провалом). На быстрых машинах короткие запросы могут не превысить порог — снизьте `-TechLogThresholdMs` или смотрите журнал под нагрузкой.

Логи установки — в `<BaseDir>\logs`.

## Матрица колонок (как на Pages)

Канон: **https://goshva.github.io/vitauto1c/?role=manager&level=order&mode=all**

(Исходник: [index.html](index.html). Роль manager, уровень Заказ, режим all.)

Связанный канон процесса/матрицы BaskakovAnton/vitauto: https://baskakovanton.github.io/vitauto/

### Ссылка с настройками (query-параметры)

| Параметр | Значения | Что задаёт |
|---|---|---|
| `role` | `manager`, `storekeeper`, `chief_mechanic`, `admin`, `supplier`, `client` | выбранная роль |
| `level` | `order` (Заказ), `line` (Деталь) | уровень статуса |
| `mode` | `all` (все статусы), `single` (по одному статусу) | режим показа статусов |
| `status` | id статуса (`new`, `acceptance`, …) или номер с 1 | статус для режима `single` |

Пример: `index.html?role=storekeeper&level=line&mode=single&status=acceptance`

Адресная строка обновляется сама при переключениях; кнопка «Скопировать ссылку» копирует текущую.

## Опросник ролей

[questionnaire.html](questionnaire.html) — пошаговый опросник (mobile first): для каждой колонки × статуса отмечается, какие роли могут редактировать, обязательность и тип данных колонки. `?level=order|line` открывает нужный уровень статуса.

- Ответы хранятся в localStorage (`vitaauto_questionnaire_v1`).
- На каждые 10% заполнения автоматически скачивается JSON; он совместим с «Импорт JSON» матрицы и содержит блок `questionnaire` для продолжения опроса на другом устройстве (меню ⋯ → «Продолжить из файла JSON»).
- «Применить в матрицу» записывает ответы в матрицу этого браузера.

## Настройки по умолчанию для всех

Умолчания матрицы лежат в [default-matrix.js](default-matrix.js) (≈20 КБ). Он собирается из «Экспорт JSON» скриптом:

```
python tools/make_default_matrix.py "column-matrix (2).json"
```

- Новый пользователь (пустой localStorage) и «Сбросить к умолчаниям» получают эти настройки.
- У кого в браузере уже сохранена своя матрица, увидит плашку «Доступны новые настройки по умолчанию» с кнопками «Применить» / «Оставить мои».
- Колонка «Агрегат» (`aggregate_fact`) добавляется генератором с правами «Госномера». У полей с правилом «обязательно одно из» (Госномер/Агрегат, Наименование/Артикул/Код А-А) отдельный флаг «Обяз.» снимается: обязательность задаёт правило группы.

## Правила заполнения полей

Список правил — под примером таблицы в матрице («Правила заполнения полей»); в экспорт JSON попадает как `fieldRules` для реализации в 1С. Справочники в прототипе демо (`DIRECTORIES` в index.html).

- Вид услуги — список: ремонт, услуга, инструмент, запчасть.
- Договор — только договоры выбранного Заказчика.
- Госномер — из справочника машин, подтягивает Марку, Модель, VIN, Двигатель, № Шасси.
- Обязательно одно из: Госномер или Агрегат.
- Наименование / Артикул / Код А-А — поиск по любому; выбор подтягивает остальные (включая Ед. изм.). Обязательно одно из трёх.
- Цена продажи = Цена (себес.) × (1 + Коэфф/100); Сумма продажи = Кол-во (ФАКТ) × Цена продажи.
- Если заполнено «Кол-во норма час товар для клиента»: коэффициент игнорируется, Сумма продажи = норма-час × Цена продажи (цена вводится вручную).

## Коды и группы колонок

Каждая колонка имеет буквенно-цифровой код: буква — группа, цифра — подгруппа, после точки — номер колонки в группе. Источник — [column-codes.js](column-codes.js), общий для матрицы и опросника.

| Код | Группа |
|---|---|
| A | Служебные |
| B | Заказ и отгрузка |
| C1 | Факт · Автомобиль / агрегат (Марка, Модель, Агрегат, Госномер, № Шасси, VIN, Двигатель) |
| C2 | Факт · Позиция (срочность, ГРЗ, территория, наименование/артикул/кол-во/ед. факт) |
| D | Номенклатура |
| E | Склад и статус |
| F1 | Цены и оплата · Себестоимость и оплата |
| F2 | Цены и оплата · Продажа (Коэфф, Цена продажи, Сумма продажи) |
| G | Поступление от поставщика |
| H | Комментарий |

В матрице группы сворачиваются (клик по строке группы, «Свернуть группы» / «Развернуть»), поиск понимает коды: `C1` — вся подгруппа, `C` — вся группа, `F2.3` — одна колонка. В экспорте JSON у колонок есть `code` и `codeGroup`.

Импорт JSON принимает файлы, где в ячейках есть колонки, известные приложению, но отсутствующие в списке `columns` файла (выгрузка другой версией страницы); неизвестные колонки/статусы пропускаются с сообщением.
