# HTTP API АРМ в 1С: публикация, установка, автотесты

HTTP-сервис `Арм_API` расширения АРМЗакупокИПродаж v2.9 — контракт `openapi/arm-pwa.openapi.yaml` (ветка `api`)
и переходы процессов [`openapi/arm-pwa-process.openapi.yaml`](../../openapi/arm-pwa-process.openapi.yaml).
URL: `http://127.0.0.1:8090/<публикация>/hs/api/arm/v1`.

| Публикация | База | Назначение |
|---|---|---|
| `/vitauto` | `D:\1c\test_fresh` | тестовая копия: автотесты пишут в неё данные |
| `/autoservice` | `C:\1c_bases\autoservice` | рабочая база (`deploy-prod.ps1`) |

## Файлы

| Файл | Что делает |
|---|---|
| `start.ps1` | запускает Apache (`D:\1c\apache`, модуль `wsap24.dll` 1С) и проверяет API; после перезагрузки Windows — снова. `-Stop` — остановить |
| `httpd-1c.conf`, `default.vrd` | конфигурация Apache и публикации тестовой базы. Apache переносит `Authorization: Bearer` в `X-Arm-Authorization`: иначе веб-расширение 1С само разбирает токен и отвечает 500 |
| `deploy-prod.ps1` | установка в рабочую базу: проверка, что база закрыта → резервная копия (файлы и прежнее расширение) → загрузка `.cfe` → безопасный режим выключен → пользователи API → публикация `/autoservice` → проверка входа |
| `prod-setup.js` | COM-часть установки: безопасный режим, пользователи `arm.*` (без ролей 1С, только API) → элементы «… (seed)» с ролями интерфейса АРМ |
| `test-endpoints.js` | все 29 операций контракта по разу: 13 чтение, 16 запись (`supplier-orders` — 501, команда формы заглушка) |
| `e2e-processes.js` | 11 сценариев `process.html` целиком запросами API, с проверкой статуса на каждом шаге |
| `fx-status.js` | фикстура COM для `test-endpoints.js` (статус строки напрямую) |

## Пользователи API

Пароль `1` (в рабочей базе — параметр `-Password` у `deploy-prod.ps1`). Вход с пустым паролем API отклоняет.

| Логин | Роль АРМ | Список |
|---|---|---|
| `arm.manager` | Менеджер | продажи, закупки |
| `arm.storekeeper` | Кладовщик | продажи, закупки |
| `arm.supply` | Снабжение | канбан снабжения |
| `arm.admin` | Администратор | все |
| `arm.mechanic` | Главный механик | продажи, закупки |

## Автотесты

```
.\tools\arm-api-1c\start.ps1
.\seed-1c.ps1 -IbDir D:\1c\test_fresh -KeepSafeModeOff   # справочники с типом и счетами учёта
node tools\arm-api-1c\test-endpoints.js
node tools\arm-api-1c\e2e-processes.js                   # все 11 сценариев, ~5 минут
node tools\arm-api-1c\e2e-processes.js stock defect      # выбранные
```

Только на тестовой базе: прогоны создают заказы, документы и меняют остатки. Сценарии «со склада» сначала
пополняют склад отдельным заказом (закупка до прихода, закрытие без отгрузки): в базе включён контроль остатков
при проведении. После прихода АРМ пересобирает строки заказа по партиям — id строк меняются, прогон находит их
заново по ключу связи.

## Установка в рабочую базу

1. Закрыть все окна 1С на базе.
2. `.\tools\arm-api-1c\deploy-prod.ps1` (резервная копия — `D:\1c\backup\autoservice_<дата>`).
3. Если в базе есть данные seed, созданные до 5.10.2026: `.\seed-1c.ps1 -KeepSafeModeOff` — дозаполнит тип и счета
   учёта номенклатуры и счета расчётов контрагентов (без них приходные и расходные накладные не проводятся).
