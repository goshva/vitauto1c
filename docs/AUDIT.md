## 3. Дефекты (приоритет)

**D-01 (P1) Колонки движения: даты не ставятся событиями из эталона.**
`pwa/src/stores/columns.js:15` задаёт набор MOVEMENT = `reserve_qty, paid_status, receipt_date, shipment_date, line_status` — 5 колонок, как в эталоне.
Но: `shipment_date` ставится в `arm/jobs.go:541` и `arm/lines.go:911` (ок). `receipt_date` в бэкенде присваивается только в `arm/supply.go:113` при смене статуса снабжения с переданной датой. В переходе «Принять по УПД» (`acceptance`) и при проведении возврата поле даты я не нашёл. Эталонный шаг 4 («провести приёмку → Дата приёмки») по коду не подтверждён. Шаг 5 («возврат → Статус строки = Возврат») — статус `return` в `matrix.go:458` есть.
Регрессионный тест: создать продажу, провести отгрузку и приёмку, затем `GET /lines/{id}` → `receiptDate != null`. Падает сейчас, если дата не ставится.

**D-02 (P1) Кладовщик и снабжение правят закупочную цену и оплату.**
`matrix.json`, права по 15 статусам: `price` (storekeeper/supply) = `.......++......` — запись в статусах `acceptance`, `to_stock`. `paid_status` у storekeeper/supply = `+++++++++++++++` (везде). ФТ п. 5: кладовщик «без цен закупки и себестоимости».
Тест: `PATCH /lines/{id}` `{price: …}` под storekeeper в статусе `acceptance` → ожидается 403, сейчас допускается матрицей.
Вопрос заказчику: считать ли колонку `price` закупочной ценой (см. D-04).

**D-03 (P1) Нет «Снять резерв» с проверкой автора.**
Поиск `reserved_by`, `unreserve`, переход «из reserve» в `arm/lines.go`/`matrix.go` ничего не дал. `reserve_qty` не редактируется ни одной ролью, кроме admin (и то `writable:false`). Права `c` («только автор») в `matrix.json` проставлены только на `cell_select` и `doc_signed_original`.
Тест: manager A ставит резерв; manager B вызывает снятие → 403 `not_author`; A → 200.

**D-04 (P2) Цена варианта поставки пишется в `sale_price`.**
`supply_options.go` `ApplySupplyOption` обновляет `sale_price` строки закупки, а `ref.supplier_offer.price` по миграции — «закупочная». Соответствие `sale_price` ↔ колонка `price` матрицы не подтверждено. Открыто.

**D-14 (P1) Возвраты без проверки роли.** Маршруты `/returns*` (`api/handlers_v2.go:26-48`) и `application.ReturnCreate/ReturnPost` не проверяют роль; в `api/` нет общего guard по ролям. Любой авторизованный (в т.ч. client, supplier) может, по коду, создать и провести возврат. ФТ: менеджер и кладовщик. Тест: client → `POST /returns` → 403. Без запуска, возможно закрыто в auth-слое — проверить.

**D-15 (P1) Право «только автор» практически не применяется.** В `matrix.json` `c` стоит только на `cell_select` и `doc_signed_original`; на ценовых, статусных и комментарных колонках — нет. Движок есть (`lines.go:400`, `markedByMe`, `denyReason`), данные не настроены.
