- [ ] **1a. Два сценария e2e падают и на v2.22, и на v2.23** (копия vitauto, seed E2E): `split_unpicked` — авто-закупке
  с поставщиком из PWA не подставляется договор поставщика («Пустой договор поставщика» при «Заказать»);
  `m06_partial_stock` — продаже 11 шт. при остатке на складе не назначается партия и не создаётся закупка
  после PATCH количества через PWA. Зависит от остатка, оставшегося после предыдущих сценариев: в прогоне 29.10 после блока 8 прошёл — сценарию нужен свой остаток (seed) или проверка до запуска. Так же `m23_prepared` (29.10, после ~15 прогонов на одной копии: свободного остатка фильтра нет). Нужно: seed перед каждым прогоном добавляет остаток (новая приходная) или сценарии закрывают свои заказы.
- [ ] **2. Пользователи arm.\* в vitauto.** `arm.storekeeper`, `arm.supply`, `arm.admin`, `arm.mechanic` созданы после
  запуска `grant-arm-roles.ps1` (26.10 их не было) — прогнать скрипт ещё раз (роль АРМ, связь с «Пользователи»,
  запись в `Арм_ПраваПользователей`). Пароль `arm.manager` с 26.10 изменён (`arm.manager` больше не подходит) —
  зафиксировать, кто и где хранит пароли тестовых пользователей; в `pwa/README.md` и на форме входа PWA написано «пароль 1».
- [ ] **3. 401 вместо 403.** При «Доступ запрещён» 1С отвечает в OData 401, PWA показывает «неверный логин или пароль».
  В PWA при 401 сделать второй запрос к объекту без прав АРМ (например `Catalog_Пользователи/$count`): 200 — значит
  пароль верный, не хватает прав, — показать это пользователю.

- [ ] **5. Пароль PostgreSQL сервера** слабый (словарный). Сменить, хранить в `%APPDATA%\postgresql\pgpass.conf`
  учётной записи, от которой идут бэкапы; обновить регистрацию баз в кластере (`rac infobase update --db-pwd`).
- [ ] **6. Регулярный бэкап.** Сейчас только вручную. Задание планировщика: `backup-1c-full.ps1 -Database vitauto

- [ ] **7. Выгрузка .dt в backup-1c-full.ps1** падает «Ошибка исключительной блокировки»: базу держат фоновые задания.
  26.10 сделано вручную: `rac infobase update --sessions-deny=on --scheduled-jobs-deny=on --permission-code=…`,
  `/UC <код>` у `DESIGNER /DumpIB`, затем снятие запрета. Встроить в скрипт (ключ `-LockForDt`, снятие в `finally`).

## P2

- [ ] **8. Автозапуск.** Apache, RAS и PWA запускаются вручную и после перезагрузки не работают.
  Apache — службой (`httpd.exe -k install -n Apache2.4-1C -f D:\1c\apache\httpd-1c.conf`), RAS — службой
  (`ras.exe cluster --service --port=1545`), PWA — собрать (`npm run build`) и отдавать `dist/` тем же Apache
  (+ прокси `/odata`), а не dev-сервером Vite.
- [ ] **9. PWA только на 127.0.0.1.** Для телефонов/других ПК: доступ по сети, правило брандмауэра, HTTPS
  (service worker PWA работает только на https или localhost).
- [ ] **10. Порт PostgreSQL 5433.** `backup-1c-full.ps1`, `restore-1c-pgsql.ps1` по умолчанию берут 5432 — на сервере
  нужен `-PgPort 5433`. Определять порт по `postgresql.conf` службы `postgresql-1c-*`.
- [ ] **11. Остановленный PostgreSQL 15** (`postgresql-1c-15`, `C:\PGDATA15`) — решить: удалить или оставить как архив.
- [ ] **12. Базы autoservice / autoservice_main** на сервере и публикация `/autoservice` — нужны ли рядом с рабочей vitauto.
- [ ] **13. Версии расширений.** В vitauto `АРМ_OData` 1.1, у `АРМЗакупокИПродаж` версия в свойствах пустая;
  в репозитории — АРМ v2.22 и `АРМ_OData` 1.2 (big fix, ещё не развёрнуты). Заполнять «Версию» расширения при сборке,
  развернуть v2.22/1.2 по плану `tasks/bugs-v2.22.md`.
- [ ] **14. Полный прогон развёртывания на чистой ВМ.** Ветка `install-1c-pgsql.ps1 -SourceDump` до этого коммита не
  вызывалась (параметр не был объявлен); проверена по частям (pg_restore, CREATEINFOBASE, конфиг Apache) — прогнать
  DEPLOY-LOCAL.md целиком на виртуальной машине.
- [ ] **15. Двойной LoadModule** `_1cws_module` в `D:\1c\apache\httpd-1c.conf` на сервере (второй добавил webinst) —
  при старте предупреждение AH01574. Убрать строку с полным путём к `wsap24.dll`.
- [ ] **16. e2e main-smoke** сверяет данные копии `autoservice_main` (группа машины «Вакуумные … (ПУ)»), на vitauto
  падает. Вынести ожидаемые значения в переменные окружения или проверять структуру, а не конкретные данные.
