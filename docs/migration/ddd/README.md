# DDD: модель предметной области АРМ vitauto для стека PostgreSQL + Go + Vue 3

Модель построена из тех же источников, что согласованы с заказчиком:
- **процесс** — [process.html](../../../process.html): 45 узлов на 6 дорожках ролей, 13 зон склада, 11 сценариев;
- **матрица и роли** — [index.html](../../../index.html) и рабочая матрица PWA `pwa/src/odata/matrix.json`: 7 ролей, 15 статусов, 57 колонок;
- **переходы статусов** — из кода PWA, `backend.js` (это перенос `Арм_API.ПереходыПроцессов` 1С).

Ничего не переписывается руками из HTML. Извлечение и генерация автоматические, а тесты падают, если источники изменились, а модель и документы не обновили.

## Обновление и проверка

```
node tools/migration/extract-domain.mjs     # после правки index.html / process.html / матрицы / переходов
node tools/migration/ddd-gen.mjs            # после правки node-map.json или domain-model.json
node --test tools/migration/tests/          # полнота и актуальность (входит в гейт G0.6)
powershell -File tools/migration/gate.ps1 -Stage 0
```

## Что модель уже показала

- **Переходы статусов, которых нет в таблице кода.** Они используются в сценариях, но выполняются заданиями, канбаном снабжения и отгрузкой. Все они описаны в `fsmAdditions`, и непокрытых переходов нет (проверяет тест).
- **Расхождение схемы и кода.** По схеме оплату (M7) контролирует менеджер, а в PWA `/supply/status` разрешён только ролям `supply` и `admin`. Решение нужно подтвердить у заказчика ([fsm.md](generated/fsm.md)).
- **Пробелы матрицы.** На пяти шагах роль не может по матрице менять колонки своего узла: P1, K2, K3, K5, P3 ([processes.md](generated/processes.md), «Наблюдения»). Это проверяется с заказчиком при переносе матрицы на этапе 4.
- **Роль `supply` (снабжение).** Она есть в матрице PWA и в 1С, но на схеме процесса у неё нет дорожки. Её действия — канбан снабжения (`/supply/status`).
