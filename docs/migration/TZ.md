# Техническое задание: перенос АРМ закупок и продаж vitauto с 1С на PostgreSQL + Go + Vue 3 PWA

Редакция 1 от 2026-10-30, ветка `migration/pg-go-vue`.

ТЗ задаёт, **что** должно быть сделано и **как это принимается**. Порядок работ и оценки — в плане [tasks/migration-pg-go-vue.md](../../tasks/migration-pg-go-vue.md). Модель предметной области — в [docs/migration/ddd/](ddd/README.md).

Каждое требование имеет номер `ТР-…` и ссылку на проверку. Тест `tools/migration/tests/tz.test.mjs` контролирует, что в ТЗ есть все контексты, узлы процесса и проверки.

## 1. Общие сведения

| | |
|---|---|
| Система | АРМ закупок и продаж Витавто (строки заказов, закупка, склад, отгрузка, возвраты) |
| Сейчас | 1С 8.3.27, «Автосервис» 3.0.11.169 + расширения АРМЗакупокИПродаж 2.23, АРМ_OData 1.3; PWA Vue 3 работает через OData 1С |
| Будет | PostgreSQL 18 (`vitauto_app`) + сервисы Go (`vitauto-api`, `vitauto-migrator`) + та же PWA Vue 3; бухгалтерия остаётся в 1С (вариант A плана) |
| Источники требований | процесс [process.html](../../process.html) (45 узлов, 11 сценариев, 13 зон), матрица [index.html](../../index.html) и `pwa/src/odata/matrix.json` (7 ролей × 57 колонок × 15 статусов), код АРМ v2.23 и PWA |
| Репозиторий | монорепозиторий `vitauto1c` (план, раздел 4) |

## 2. Цели

1. Перенести учёт АРМ без потери данных: каждая запись 1С должна оказаться в новой базе или в архиве `legacy`, и это подтверждается сверкой.
2. Сохранить процессы, роли и матрицу прав, согласованные в process.html и index.html, и исполнять их на сервере.
3. Добавить:
   - склады и ячейки в интерфейсе;
   - универсальный импорт таблиц;
   - обновление страниц в реальном времени;
   - документированный API (Swagger);
   - обмен с бухгалтерией.

## 5. Порядок разработки и контроля

- Работа идёт по этапам 0–11 плана, ремонтная зона и порталы — на этапе 12. Этап закрывается гейтом `tools/migration/gate.ps1 -Stage N` (G0–G11) и протоколом в `docs/migration/gates/`.
- Каждый узел процесса пишется по шагам [ddd/04-development-process.md](ddd/04-development-process.md): модель → сопоставление → документы → контракт → тесты до кода → схема → домен → API → политики и WS → PWA → паритет с 1С → гейт.
- Тесты: каталог [ddd/generated/test-catalog.md](ddd/generated/test-catalog.md) (T, S, M, F, FR) и наборы R1–R9, r01–r05, w01–w04, i01–i08, x01–x06.

## 6. Приёмка

1. **Этап принимается**, когда протокол гейта показывает «Итог: этап закрыт» и ручная проверка отмечена.
2. **Переключение** допускается при выполнении G11.1–G11.3: пять ночных сверок подряд без расхождений и закрытые гейты 0–10.
3. **Акт переключения** подписывается после финальной сверки (R1–R9 = 0) и недели работы без блокирующих ошибок. Откат возможен в течение этой недели (план, раздел 16).
