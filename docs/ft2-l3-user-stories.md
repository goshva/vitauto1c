## Юзер-стори

### US-3.1 — Кладовщик без цен закупки и себестоимости
**Как** кладовщик, **я хочу** работать со складскими документами и колонками движения, **чтобы** не видеть и не менять
закупочные цены и себестоимость; **как** менеджер по продажам, **я хочу** полный доступ к заказу и ценам.

**Критерии приёмки (Given/When/Then):**
- Given роль «Кладовщик», When открываю строку в статусах «Приемка»/«На складе»,
  Then поля «Цена (себес.)», «Сумма (себес.)», «РРЦ», «Наценка, %», «Цена продажи» — недоступны для правки.
- Given роль «Менеджер по продажам», Then те же поля доступны в статусах заказа.
- Given любая роль, When сохраняю правку себестоимости кладовщиком, Then 403 `matrix_denied`.

**Сейчас:** 🔴 тест `test_storekeeper_without_cost_price` падает — у кладовщика и снабжения есть правка `price`
в «Приемка»/«На складе»; у кладовщика также открыта правка `paid_status`, `invoice_number`, `invoice_date`.
**Где смотреть:** `pwa/src/odata/matrix.json` (роли `storekeeper`, `supply`) → `backend/internal/arm/matrix.go` (`denyReason`) →
`pwa/src/stores/matrix.js`. Правка — в матрице, ветка `matrix/canon-author-only`, генератор `tools/gen_pwa_matrix.py`.

### US-3.2 — Оплата и счета не у кладовщика
**Как** менеджер, **я хочу**, чтобы оплату и счета по закупке вёл он, **а не** кладовщик.

**Критерии:** Given роль «Кладовщик», Then поля «Оплачено», «Счёт №», «Дата счёта» — только просмотр (или скрыты).

**Сейчас:** 🔴 `test_storekeeper_without_payment_edit` — у кладовщика `+` во всех 15 статусах.

### US-5.1 — Снять резерв только автору
**Как** снабженец/менеджер, **я хочу** снять резерв, который поставил сам, и **не хочу**, чтобы его снял другой
пользователь, **чтобы** не потерять зарезервированный остаток.

**Критерии:** Given строку зарезервировал пользователь A, When пользователь B нажимает «Снять резерв»,
Then 403 `not_author`; When A нажимает, Then резерв снят.

**Сейчас:** 🔴 `test_reserve_author_only` — `reserve_qty` доступен только админу (`...............` у всех остальных),
значит менеджер/снабжение вообще не могут ни поставить, ни снять резерв, и правило автора негде включить.
**Где смотреть:** матрица Н2 → `backend/internal/arm/matrix.go` (случай `c` + `markedByMe`) → `lines.go` `markedByMe`.

### US-9.1 — Изменение документа только автором
**Как** автор строки, **я хочу** единолично отмечать «Документ подписан оригинал», **чтобы** контроль документов
не переписывал другой пользователь.

**Критерии:** Given флаг ставит пользователь A, When B пытается его изменить, Then 403 `not_author`;
When A или администратор, Then изменение проходит.

**Сейчас:** 🟢 на ветке `matrix/canon-author-only` (появился `c` в «Отгружено»/«Возврат» для 4 ролей,
админ — полный доступ). ⚠️ Важно: в движке `c` проверяет `markedByMe` — это **автор отметки строки**, а не «автор документа».

### US-9.2 — Просмотр документов по профилю, админ — полный доступ и НСИ
**Как** администратор, **я хочу** полный доступ и ведение НСИ; **как** остальные роли — просмотр по профилю.

**Критерии:** Given роль «Администратор», Then все поля доступны; Given другая роль, Then просмотр без правки.
**Сейчас:** 🟢 полный доступ админа подтверждён; ⚠️ «просмотр по профилю» в матрице не выражается —
все колонки принудительно `visible: true` (`enforceConstraints` в `index.html`: «всё видно всем»).

## Вопросы заказчику с развилками

### Q1 (п. 3). Себестоимость у кладовщика
В матрице у кладовщика и снабжения есть правка «Цена (себес.)» в «Приемка»/«На складе» (`.......++......`),
а ФТ говорит «без цен закупки и себестоимости».

| Вариант | Что делаем | Последствие |
|---|---|---|
| **A (рекомендую)** | убрать правку `price` у `storekeeper` и `supply` | тест `test_storekeeper_without_cost_price` зелёный; себестоимость приходит из приходной накладной 1С |
| B | оставить только просмотр | нужен механизм скрытия/только-чтения себестоимости — сейчас в матрице видимость не настраивается |
| C | оставить как есть и поправить ФТ | зафиксировать в ТЗ, тест переписать под новое требование |

### Q2 (п. 3). Оплата и счета у кладовщика
`paid_status`, `invoice_number`, `invoice_date` = `+` во всех 15 статусах у кладовщика.

| Вариант | Что делаем | Последствие |
|---|---|---|
| **A** | убрать правку у кладовщика (оплата — менеджер/снабжение) | тест `test_storekeeper_without_payment_edit` зелёный |
| B | оставить только просмотр | нужен режим только-чтения по колонке |
| C | оставить правку (кладовщик видит оплату при приёмке) | изменить ФТ, тест убрать |

### Q3 (п. 5). Как включить «снять резерв только автор»
Сейчас Н2 доступен только админу, поэтому правило нечего ограничивать.

| Вариант | Что делаем | Последствие |
|---|---|---|
| **A (рекомендую)** | дать `c` (author-only) менеджеру и снабжению на Н2 в «Резервирование»/«Комплектация» | тест `test_reserve_author_only` зелёный; движок `c` уже готов |
| B | дать `+` и проверять автора отдельным кодом (`not_author`) | правило уходит из матрицы в код, тесты писать на код |
| C | оставить только админа, признать п. 5 невыполнимым | правка ФТ, тест удалить |

**Уточнение к Q3:** «автор резерва» — это `АвторСтроки` (кто отметил строку) или нужен отдельный реквизит
«кто поставил резерв»? От этого зависит, попадёт ли правило в `c` или потребует нового поля.

### Q4 (п. 9). Кто считается «автором документа»
Движок `c` проверяет `markedByMe` — автора **отметки строки** (`АвторСтроки`), а не автора документа.

| Вариант | Что делаем | Последствие |
|---|---|---|
| **A (рекомендую, если «документ» = строка)** | оставить как есть | тесты п. 9 зелёные, ничего не меняем |
| B | автор = автор документа-основания (заказ покупателя) | доработка `denyReason`: сейчас `c` смотрит только `markedByMe`; новые L1/L2-тесты |
| C | автор = тот, кто первым поставил флаг | новый реквизит + правила |

### Q5 (п. 9). «Просмотр — по профилю»
В матрице все 57 колонок видимы всем ролям (видимость не настраивается).

| Вариант | Что делаем | Последствие |
|---|---|---|
| **A (рекомендую)** | оставить: ограничения только на изменение | тесты зелёные, объём 0 |
| B | ввести скрытие колонок по профилю | новая настройка матрицы + UI + API, отдельная оценка |

### Q6 (п. 9). Админ и символ `c`
У админа сейчас `+` (полный доступ), но движок не делает исключения для админа при `c`.

| Вариант | Что делаем | Последствие |
|---|---|---|
| **A (рекомендую)** | зафиксировать правило «у админа всегда `+`, никогда `c`» | тест `test_admin_full_access` уже это проверяет |
| B | добавить в `denyReason` обход для админа | матрица сможет ставить `c` и админу; больше кода и тестов |
