# Задача: номер отгрузки — только чтение в матрице → системное заполнение

## Цель

Колонка **«Номер отгрузки»** (`shipment_number` / В2 / поле регистра `НомерОтгрузки`) в каноне матрицы прав — **только чтение для всех ролей** на уровне статуса «Заказ». Значит, пользователь не вводит номер вручную: значение появляется **системно** (из документа отгрузки / проведения РН / согласованного сценария), а в АРМ показывается как факт.

Дата отгрузки (`shipment_date` / В1 / `ДатаОтгрузки`) в матрице редактируется выборочно (менеджер — в `ready_to_ship`; кладовщик/админ — шире). Её судьба в этой задаче — согласовать отдельно; **фокус задачи — номер**.

## Контекст и разрыв (as-is)

| Слой | Факт |
|---|---|
| Матрица (канон) | `https://goshva.github.io/vitauto1c/?role=manager&level=order&mode=all` — `shipment_number` editable = none у manager / storekeeper / chief_mechanic / admin / supplier / client во всех статусах order |
| Код v2.7 | Кнопка **«Заполнить дату и номер отгрузки»** (`ЗаполнитьДатуИНомерОтгрузкиДляЗаказа` → `ФормаВводаРеквизитовОтгрузки`) пишет в регистр **и** `ДатаОтгрузки`, **и** `НомерОтгрузки` по строкам заказа с партией |
| Процесс | `process.html`: M12 (ведомость), K5 (отгрузка) опираются на `shipment_date` / `shipment_number`; печатной формы ведомости в расширении нет |

**Вывод для БТ:** ручной ввод номера кнопкой противоречит матрице («только чтение у всех» = системное заполнение).

## Границы

**Входит:**
- зафиксировать правило: `НомерОтгрузки` не редактируется ни одной ролью АРМ (соответствие матрице);
- определить **один** системный момент заполнения (см. варианты ниже) и реализовать запись в регистр для строк заказа;
- в UI: колонка `НомерОтгрузки` — только просмотр; убрать или сузить ручной ввод номера (кнопка/диалог);
- синхронизация с уже существующей `РасходнаяНакладная` в регистре, если источник — РН.

**Не входит (отдельные задачи):**
- ACL видимости/доступности всех кнопок по роли×статусу;
- полный маппинг статусов АРМ ↔ статусы матрицы;
- печатная «отгрузочная ведомость» (M12);
- изменение канона матрицы (если продукт решит вернуть ручной EDIT номера — это смена матрицы, не этой задачи).

## Варианты источника номера (выбрать один на апруве)

1. **Из расходной накладной** — при проведении/записи РН проставить `НомерОтгрузки` = номер документа РН (или согласованный реквизит) во все связанные строки АРМ.
2. **Нумератор / служебный документ отгрузки** — отдельный объект или общий модуль выдаёт номер; АРМ только читает.
3. **Внешний контур** (ТК / складской документ) — импорт номера в регистр без UI редактирования.

Рекомендация по текущему коду: **вариант 1**, т.к. в регистре уже есть `РасходнаяНакладная`, а процесс K5 связывает отгрузку с РН.

## Что сделать

1. **Апрув источника** — зафиксировать в задаче/протоколе выбранный вариант (1/2/3).
2. **Запись системно** — в точке проведения/записи источника заполнять `НомерОтгрузки` по `ДокументЗаказПокупателя` / ключам строк (не через диалог пользователя).
3. **UI АРМ**
   - колонка номера — `ТолькоПросмотр` для всех ролей (в т.ч. админ, если матрица RO);
   - кнопка «Заполнить дату и номер отгрузки»: либо убрать поле номера из диалога и оставить только дату (если дата остаётся ручной), либо заменить кнопку на действие «сформировать отгрузку», которое создаёт/проводит РН и само пишет номер;
   - не оставлять путь, где пользователь свободно вводит произвольный номер в регистр.
4. **Дата отгрузки** — явно решить в апруве: остаётся ручной ввод по матрице (В1) или тоже уходит в систему вместе с РН; в коде развести запись даты и номера.
5. **Приёмка** — сценарий: отгрузить заказ → в АРМ у строк появился номер без ручного ввода; повторное открытие формы показывает то же значение; роль менеджер/кладовщик не может изменить номер из ячейки/диалога.

## Критерии приёмки

- [ ] В матрице `shipment_number` по-прежнему RO для всех (канон не ломаем без отдельного решения).
- [ ] После системного события отгрузки `НомерОтгрузки` заполнен в `Арм_ДанныеЗакупокИПродаж` у нужных строк.
- [ ] Нет UI-пути ручного ввода номера отгрузки в АРМ (или путь отключён/заблокирован).
- [ ] Поведение согласовано с наличием `РасходнаяНакладная` в строке (если выбран вариант 1).
- [ ] Кратко описано в комментарии кода / этой задаче: откуда берётся номер.

## Связанные разрывы (не блокируют старт, но учесть)

- Статусы АРМ (`Черновик` / `ВРаботе` / `Отгружено`) ≠ статусы матрицы (`ready_to_ship` / `shipped`) — момент системной записи нужно привязать к документу/событию, а не только к флагу формы.
- Кнопки АРМ сейчас не режутся матрицей по ролям — эта задача про **данные номера**, не про полный ACL кнопок.
