v1 → v2.0 продукт

Источник: diff/АРМЗакупокИПродаж_v1__v2.0.md

  • Таблица продаж начинает строить колонки по матрице прав: заголовки, порядок, только просмотр там, где в матрице нельзя править.
  • Поля, которых ещё нет в данных, показываются как заглушки (подсказка, что колонка зарезервирована).

v2.0 → v2.1 продукт

Источник: diff/…v2.0__v2.1.md, задача admin-columns-matrix.md

  • Роль интерфейса «Администратор»: открывается форма продаж, можно менять разрешённые поля матрицы (двойной щелчок → ввод).
  • В регистр добавлены реальные поля вместо части заглушек: документ подписан, марка/модель/агрегат/госномер/VIN/двигатель, норма-час, РРЦ, оплачено, территория отгрузки поставщиком и др.
  • Договор и № п/п берутся из данных, а не из пустых констант.

v2.1 → v2.1.1 из задачи

Отдельного diff в репо нет — tasks/admin-columns-matrix.md

  • Админ правит разрешённые колонки прямо в ячейке (не только через диалог двойного щелчка).
  • Исправлен заголовок «№ Шасси».
  • Для администратора при выборе ячейки не действует жёсткий фильтр «только В работе / Собран / Черновик».

v2.1 → v2.2 продукт

Источник: diff/…v2.1__v2.2.md, contract-filter-by-customer.md

  • Колонка «Договор с заказчиком»: в списке только договоры выбранного заказчика.
  • Без заказчика — предупреждение «сначала выберите заказчика».
  • При записи чужого договора — отказ с текстом ошибки.

Источник: diff/…v2.2__v2.3.md (склейка admin + договор)

v2.3 → v2.4 из задачи

Diff CFE нет — seed-local-db.md / появление ролей

  • В перечислении ролей интерфейса: кладовщик, главный механик, клиент, поставщик (помимо менеджера/админа/снабжения).
  • Для них открывается форма продаж; полноценные права «роль × статус» появятся позже (v2.11).

v2.4 → v2.5 из задачи

Diff CFE нет — matrix-statuses-codes-formulas.md

  • В статусах строки АРМ добавлены значения под расширенную матрицу (15 статусов): «Ожидаем поступление», «Резервирование», «Возврат».
  • Кнопок перехода в UI ещё нет — статусы может выставлять seed / поздние версии.

v2.5 → v2.6 из задачи

Diff CFE нет — matrix-statuses-codes-formulas.md § v2.6

  • Порядок колонок как в матрице (норма-час перед «Коэфф»).
  • В заголовках — коды матрицы (Е4, Р2…).
  • Цена продажи = РРЦ × коэффициент, иначе себестоимость × коэффициент; коэффициент — множитель (1,15), не проценты «+15».
  • Сумма себестоимости = цена × количество; сумма продажи — с учётом нормы-часа или количества.

v2.6 → v2.7 из задачи

Diff CFE нет — matrix-statuses-codes-formulas.md § v2.7

  • Колонка «Есть дефицит» убрана с экрана (в матрице её нет); подсветка дефицитных строк и отбор «только с закупками» остаются.
  • Заголовок «Кол-во» с кодом Н0.

v2.7 → v2.8 продукт

Источник: diff/…v2.7__v2.8.md, price-qty-sum.md

  • При смене количества (в том числе двойным щелчком) сразу пересчитываются суммы себестоимости и продажи.
  • Итог по выделенным строкам — сумма продажи (кол-во × цена), а не сумма «цен за штуку».
  • При фиксации партии в регистр пишется цена за единицу, затем пересчёт сумм.

v2.9 не продукт

Номер v2.9 относится к лабораторной ветке process-api (HTTP-сервис АРМ, PWA, e2e). В корне репозитория нет продуктового АРМЗакупокИПродаж_v2.9.cfe в линии «тонкий клиент». Следующий продуктовый шаг после v2.8 — сразу v2.10.

v2.8 → v2.10 продукт

Источник: diff/…v2.8__v2.10.md, patch-notes-v2.10.md

  • Номер отгрузки заполняется системой из номера расходной накладной; ручной ввод убран; в диалоге остаётся только дата.
  • Кнопки статусов Резервирование / Ожидаем поступление / Возврат (MVP, изначально для администратора).
  • Смена заказчика очищает договор, если он не принадлежит новому контрагенту.
  • Галка «Документ подписан оригинал» снимает автора строки и отметку (минимум unlock по А3).

v2.10 → v2.11 продукт

Источник: diff/…v2.10__v2.11.md, patch-notes-v2.11.md; тесты tools/test_arm_matrix_rights.py (71)

  • Права по матрице (роль × статус строки × поле): модуль Арм_МатрицаПрав, генерация из default-matrix.js. Нет записи роли — править нельзя.
  • Администратор сохраняет широкий whitelist полей без привязки к статусу (как в v2.1.1); номер отгрузки и статус «из ячейки» не правятся.
  • Кнопки MVP-статусов доступны менеджеру и администратору.
  • Пять бывших заглушек стали полями регистра: № шасси, кол-во в резерве, кол-во в пути, дата и № УПД.
  • «Ед. изм. (ФАКТ)» — выпадающий список: шт, компл, л, кг, м, н/ч.
  • Минимальная проверка обязательных полей при смене статуса (без поломки проведения документов).
  • На форме снабжения — запрет чужим ролям жать цепочку/отметки.

v2.11 → v2.12 продукт

Источник: diff/…v2.11__v2.12.md, patch-notes-v2.12.md; тесты 76 OK

  • H01: «Дата получения» (S2) вводится на продажах по ACL; А1 — личная отметка автора (D11=A).
  • H02: whitelist переходов для 3 кнопок статусов (из закрытых / в тот же — отказ).
  • H03: цепочка снабжения остаётся ролевым whitelist (D10=A), не матрица line_status.
  • H04: УПД из ПН — one-shot без затирания ручных; Н2/Н3 не трогали.
  • H05: бит creator по-прежнему отложен (docs).

Итог: что умеет текущий tip v2.12

  • Рабочий стол продаж/закупок с колонками и кодами матрицы.
  • Формулы цены и сумм; пересчёт при смене количества.
  • Админ и (по матрице) другие роли правят поля с серверной проверкой прав.
  • Договор привязан к заказчику; отгрузка даёт системный номер РН.
  • Статусы резерв / ожидаем / возврат — кнопками (MVP), не полной схемой process.html.
  • Новые учётные колонки (шасси, резерв, путь, УПД) и ед.изм. факта.
Не закрыто приёмкой в предприятии: LoadCfg v2.11 на тестовую ИБ и ручной прогон формы. Merge в dev — отдельное решение. Полные возвраты, печать ведомости, механик, процессный seed — вне этой линейки версий (есть только планы в tasks/).
