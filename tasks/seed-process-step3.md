## Шаг 3 (будущий): сквозной процесс

Цель — набор строк `Арм_ДанныеЗакупокИПродаж` в **каждом** статусе матрицы с реальными связями, чтобы тестировщик под любой ролью видел и пробовал каждую ячейку ACL без ручной подготовки.

| Блок | Содержимое |
|---|---|
| Строки по статусам | по 2–3 строки на статус: Черновик, В работе, Заказано/Оплачено, В пути, Приходуется, На складе, Комплектуется, Собран, Отгружено, Возврат, Заблокировано фоном |
| Заполнение полей | заведомо **полные** строки (дата заказа, № заказа клиента, кол-во>0, госномер/агрегат, поставщик) и **неполные** (для проверки T08 и отказов) |
| Связи | `ДокументПриходнаяНакладная` (если есть в УНФ — приходная накладная из seed), `ДокументРасходнаяНакладная` для «Отгружено»; `АвторСтроки`/`ОтметкаСтроки` разными пользователями (проверка А3) |
| Поля T05 | `НомерШасси`, `КоличествоВРезерве`, `КоличествоВПути`, `ДатаУПД`, `НомерУПД` — часть заполнена, часть пуста |
| Единицы | `шт`, `л`, `н/ч`, `компл`, `кг`, `м` |
| Мульти-пользователь | строки, отмеченные «Менеджером (seed)» и «Кладовщиком (seed)» |

## Правила реализации

- Идемпотентность: повторный запуск не плодит дубли (ключ — `ИдентификаторЗаписи` с префиксом `seed-`).
- Запись в регистр не через документы, не триггерит фоновые задания; **не** вызывает T08-валидацию (она только в UI).
- Откат: удаление записей с префиксом `seed-` отдельным флагом `-Cleanup` (не реализован).
- Защита от боевой ИБ — уже в `seed-1c.ps1` (`-AllowProd`).
