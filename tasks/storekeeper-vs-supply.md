# T07 — Кладовщик vs Снабжение (решение D3)

**Статус (05.10.2026):** документ + минимальная защита записи. Решение **D3 принято без остановок:** две формы остаются — `ФормаСнабжение` (цепочка закупки) и основная `Форма` (продажи/ACL); ACL кладовщика — на основной `Форма`.

## Роли и маски (D1d)

| Роль АРМ | Бит матрицы | Комментарий |
|---|---|---|
| Кладовщик | 2 (storekeeper) | в матрице |
| **Снабжение** | 2 (= storekeeper, D1d) | есть в 1С (`Арм_РолиИнтерфейса.Снабжение`), в матрице 6 ролей отдельной вкладки нет → маска storekeeper |

В ТЗ — «Кладовщик»; в коде исторически «Снабжение» (форма `ФормаСнабжение`). Конфликт названий зафиксирован в `process.html` (узел K1).

## Кто с какой формой работает

| Форма | Что делает | Права |
|---|---|---|
| `Форма` (основная, продажи) | колонки матрицы, правка полей строки | ACL роль × статус × поле (`Арм_МатрицаПрав`): кладовщик/снабжение правят «Номенклатура» в «Приходуется»/«На складе», «Дата получения», «Дата УПД»/«№ УПД» в тех же статусах, «Документ подписан оригинал» в «Отгружено»/«Возврат» и т.д. |
| `ФормаСнабжение` | цепочка закупки Оплачено → Товар в пути → Приходуется → На складе → Комплектуется → Собран; «Дата получения» | см. ниже |

## Что проверено (spot-check `ФормаСнабжение`)

| Запись | Защита до T07 | Защита после |
|---|---|---|
| «Дата получения» (`ИзменитьДатуПоступленияНаСервере`) | ACL по полю `ДатаПоступления` (v2.11, T01) | без изменений |
| Смена статусов цепочки (`Арм_ОбщегоНазначенияАРМ.ИзменитьСтатусыВРегистреСнабжения`, 6 кнопок) | **не было вообще** (любой пользователь с доступом к форме) | через общую функцию `ОтказРолиСнабжения()`: роль строго из `Арм_ПраваПользователей` (D1b): разрешено Менеджер, Снабжение, Кладовщик, Администратор; запись отсутствует / Клиент / Поставщик / ГлавныйМеханик — отказ с текстом. Проверка на сервере, в единой точке (функция вызывается только из этой формы) |
| Отметки строк (`ИнвертироватьФлагНаСервере`, `ВыделитьВсеСтрокиЗаказаНаСервере` на `ФормаСнабжение`) | только авторская защита `АвторСтроки` | тот же гейт ролей `Арм_ОбщегоНазначенияАРМ.ОтказРолиСнабжения()` (Менеджер, Снабжение, Кладовщик, Администратор; нет записи / Клиент / Поставщик / ГлавныйМеханик - тихий выход + запись в журнал `АРМ.ОтказПрав`). Побитовый ACL колонки А1 (`cell_select`) не применяется (как и к цепочке закупки) - backlog T02 |

**Почему не матричный ACL на смену статуса закупки:** по маске `line_status` менять статус вправе только менеджер (бит 1; админ — исключение D2). Цепочка закупки исторически — работа Снабжения/Кладовщика; применить матрицу «в лоб» значило бы закрыть кнопки роли, для которой форма создана. Это **открытый вопрос владельцу** (не принятое решение): либо расширить матрицу (кладовщику право на `line_status` в статусах закупки), либо переопределить роли кнопок. Сейчас — минимальный fail-closed без изменения рабочего процесса.

## Не сделано (вне minimal)

- Нет отдельной формы кладовщика/приёмки (K1–K9 из `process.html`), печати сборочного листа, зон склада.
- Объединение форм не планируется (D3).
- Права ролей 1С на объекты (не UI ACL) — отдельный вопрос.
