# ACL «роль × статус строки × поле» — модель v2.11 (T01)

Статус: реализовано 05.10.2026 в `src/АРМЗакупокИПродаж_v2.11` (общий модуль `Арм_МатрицаПрав`). Решения владельца — [impl-plan-matrix-arm.md](impl-plan-matrix-arm.md), D1…D1e. Маппинг статусов — [status-map-matrix-arm.md](status-map-matrix-arm.md).

## Как это работает

1. **Источник правил** — `default-matrix.js` (канон Pages: вкладка `manager`, уровень `order`), 15 статусов × 50 колонок, биты ролей `manager=1, storekeeper=2, chief_mechanic=4, admin=8, supplier=16, client=32`. Биты `required (64)` и `creator (128)` в ACL не участвуют (D1c: creator отложен, **не** мапится на `АвторСтроки`).
2. **Генерация**: `python tools/generate_arm_matrix_rights.py` читает матрицу и пишет BSL `Арм_МатрицаПрав` + регистрирует модуль в `ConfigurationExtension.json`. Руками модуль не правят — тест сверяет его с генератором.
3. **Проверка**: `Арм_МатрицаПрав.МожноРедактироватьПоле(Роль, СтатусСтроки, ИмяПоляРегистра)`. Порядок гейтов:
   1. роль не задана (нет записи в `Арм_ПраваПользователей`) → **запрет** (D1b, fail-closed);
   2. статус `ЗаблокированоФоном` → **запрет всем**, включая администратора (пары в матрице нет);
   3. роль `Администратор` → поле входит в whitelist v2.1.1 **без проверки статуса** (D1e=B), матрица не применяется;
   4. остальные роли → бит роли в ячейке `[статус матрицы][колонка]`; `Снабжение` = `storekeeper` (D1d).
4. **Где вызывается** (всегда на сервере, статус строки читается из регистра по `ИдентификаторЗаписи`, а не берётся от клиента):
   - `РегистрыСведений.Арм_ПраваПользователей.ОтказПоПравамНаПолеСтроки(Ид, Поле)` → `Form.ОтказПоПравамАРМ` → `ПроверитьПравоНаПолеИлиОтказать` в каждой серверной процедуре записи (12 писателей) и в `ЗаписатьПолеСтрокиАРМ`;
   - клиент до диалога ввода (`ДанныеАРМОтображениеВыбор`, `ОбработатьВыборАдминистратора`) — быстрый отказ без диалога;
   - `ФормаСнабжение.ИзменитьДатуПоступленияНаСервере` (обработчик мёртвый, но закрыт);
   - кнопки статусов (T03/D2): `РольМожетМенятьСтатусыАРМ` (Менеджер или Администратор, роль строго из регистра) + по каждой строке `МожноРедактироватьПоле(Роль, СтатусСтроки, "СтатусСтроки")`; администратор — всегда.
5. **Мягкая роль** `ПолучитьРольИнтерфейсаПользователя` (нет записи → Менеджер) оставлена **только** для выбора формы: пользователь без записи открывает АРМ на просмотр. Для прав используется `ПолучитьРольИнтерфейсаСтрого` (нет записи → пустая ссылка → запрет).
6. **Отчёт D1b**: `РегистрыСведений.Арм_ПраваПользователей.ПользователиБезПравАРМ()` — пользователи без записи (запускать на тестовой ИБ из консоли запросов/внешней обработки).

## Известные ограничения

- Матрица описывает строки **продаж**. Для строк закупок отдельной матрицы нет; ACL применяется к тем же полям регистра (`Поставщик`, `Договор`, `Цена`, `Количество` в закупках пишутся теми же процедурами).
- Флажок `ОтметкаСтроки` (А1): **D11=A** (v2.12) — личная отметка автора строки; матричный `cell_select` не применяется; чужую отметку сервер отвергает.
- Бит creator (128): **D1c′=A** (H05) — по-прежнему отложен, не мапится на `АвторСтроки`.
- Проверки выполнены на уровне текста/данных BSL (платформы 1С в среде нет): `CheckModules`, `LoadCfg` и клик-проверка в UI — шаги T00/T12a на тестовой ИБ.
- Расхождения вкладок ролей с каноном manager (~32 ячейки) — в `tools/_generated_matrix_rights.json` (генерируемый отчёт, в коммит не входит) и `tasks/acl-matrix-snapshot.md`.
