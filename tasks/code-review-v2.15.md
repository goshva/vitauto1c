## Найдено — по важности

### 1. Ставка НДС 20% зашита в код — приходные накладные получают 20% вместо 22%
`CommonModules/Арм_ОбщегоНазначенияАРМ` → `НайтиСтавкуНДС()` (стр. ~1406): ищет ставку по наименованию «20%» или размеру 20.
Используется в `ИзменитьСтатусыВРегистреСнабжения` (стр. 1143, 1211) при создании **приходной накладной** на статусе «Собран».
С 2026 года основная ставка — 22% (в seed уже есть форма оплаты «Безнал (НДС 22%)»).
**Последствие:** суммы НДС в ПН, созданных из АРМ, неверные.
**Предложение:** брать ставку из номенклатуры/договора или из настройки; минимум — искать 22%.

### 2. Незакрытая транзакция при загрузке пустого заказа
`DataProcessors/АС_АРМ2/Forms/ФормаЗагрузкиДанных` → `ЗагрузитьДанныеНаСервере()` (стр. ~27–40):
`НачатьТранзакцию()`, и если в загруженных данных нет строк — `Возврат Неопределено` **без** `ЗафиксироватьТранзакцию/ОтменитьТранзакцию`.
**Последствие:** платформа откатит транзакцию в конце серверного вызова с ошибкой «транзакция не была завершена»; пользователь видит невнятную ошибку вместо «нет строк для загрузки».
**Предложение:** `ОтменитьТранзакцию()` перед `Возврат Неопределено` (или проверять строки до начала транзакции).

### 3. Состояние заказа «В работе» никогда не создаётся
`НайтиПоНаименованию` возвращает **пустую ссылку**, а не `Неопределено`, поэтому ветка `Если … = Неопределено` не выполняется:
- `Арм_ДанныеЗакупокИПродажФон` стр. 290, 719, 875;
- форма `АС_АРМ2.Форма` стр. 3419 (там же `СостояниеЗаказа.Ссылка` от пустой ссылки).
**Последствие:** в чистой базе без элемента «В работе» заказы поставщику/покупателя создаются с пустым состоянием.
**Предложение:** `Если Не ЗначениеЗаполнено(…)`; лучше — предопределённый элемент или поиск по коду.

### 4. Транзакции с нарушением шаблона (риск «транзакция уже отменена»)
- `Арм_ДанныеЗакупокИПродажФон.СформироватьЗаказыФоновоеЗадание` — `ОтменитьТранзакцию()` внутри «Попытки» (стр. 145, ветка «требуется сплит») и затем повторно в «Исключении» (стр. 234 под `ТранзакцияАктивна()`); `ЗафиксироватьТранзакцию` не последняя в «Попытке» (стр. 225).
- `Арм_ОбщегоНазначенияАРМ.ПолучитьОстаткиПоСтрокам` — `НачатьТранзакцию` внутри условия, тело (стр. ~35–285) **без** «Попытки»: исключение в цикле оставит внутреннюю транзакцию открытой; фиксация — только в конце (стр. 292).
- `Арм_ОбщегоНазначенияАРМ.ИзменитьСтатусыВРегистреСнабжения` — в «Исключении» сначала журнал, потом `ОтменитьТранзакцию()` (стр. 1225). Журнал пишет в независимом режиме и не падает, но откат должен быть первым.
**Предложение:** привести к стандарту `НачатьТранзакцию(); Попытка … ЗафиксироватьТранзакцию(); Исключение ОтменитьТранзакцию(); … КонецПопытки;`.

### 5. Удаление элементов отбора во время обхода коллекции
Форма `АС_АРМ2.Форма`, стр. 3888 и 3920 (`Для Каждого … Цикл … Элементы.Удалить(…)`).
**Последствие:** при двух подряд подходящих элементах второй пропускается — отбор может задвоиться.
**Предложение:** собрать удаляемые в массив, удалить после цикла (или обход с конца по индексу).

### 6. Запросы в цикле (производительность)
Форма `АС_АРМ2.Форма` стр. 3458, 3495, 4121, 4277, 4292; `Арм_ОбщегоНазначенияАРМ` стр. 1173 (`ИзменитьСтатусыВРегистреСнабжения` — запрос на каждый заказ поставщику).
При десятках строк незаметно, при сотнях — заметно.

### 7. Мёртвый код
- `ПриходнаяНакладная`: перехваты `&После("ПриЗаписи")` и `&После("ОбработкаПроведения")` пустые (тело закомментировано), `ИдентификацияВАРМ()` не вызывается — платформа вызывает перехваты на каждой записи/проведении впустую.
- `Возврат;` перед кодом: форма `АС_АРМ2.Форма` стр. ~2045 (поле «Вид операции»), `ФормаСнабжение` стр. ~572 (поле «Дата отгрузки») — функциональность отключена «заглушкой».
- Не вызываются: `Арм_ОбщегоНазначенияАРМ.ЗаписатьСтрокуАРМ` (стр. 610), `СоздатьНовуюСтрокуПродажи` (664), `Арм_МатрицаПрав.ПоляВводаПоACL` (278); переменные `Пользователь` (Фон, стр. 26), `ТекущийЗаказТребуетСплита` (205).

### 8. Мелочи
- `ТекущаяДата()` вместо `ТекущаяДатаСеанса()` — форма `АС_АРМ2.Форма` стр. 2123, `ФормаСнабжение` стр. 576.
- `ЗаказПокупателя.Арм_ПередЗаписью/Арм_ПриЗаписи`: проверка `Ссылка.ПометкаУдаления` читает пометку из базы, а не у записываемого объекта (`ЭтотОбъект.ПометкаУдаления`). Сейчас безвредно (ветка только для новых документов), но вводит в заблуждение.
- 14 конструкторов `Новый Цвет/Шрифт` в форме АРМ (стр. 1583–1780) — по стандарту лучше элементы стиля; функционально не ошибка.
