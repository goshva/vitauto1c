# T08 — Авто, autofill, required / oneOfRequired

**Статус (05.10.2026):** Phase A закрыта выбором **C** («только ручной ввод в MVP, без нового справочника ТС»); минимальная UI-валидация обязательных полей реализована в `src/АРМЗакупокИПродаж_v2.11`. Autofill по госномеру **не делается**.

## Phase A — разведка и выбор

Правила из `index.html` (`FIELD_RULES`, экспортируются как `fieldRules`; в `default-matrix.js` их нет):

| Правило | Суть | Статус в 1С |
|---|---|---|
| `autofill` по `gosnomer_fact` (справочник машин `vehicles`) | выбор госномера подставляет Марку, Модель, VIN, Двигатель, № Шасси | **не реализуется** (вариант C) |
| `oneOfRequired`: `gosnomer_fact` / `aggregate_fact` | заполнено одно из «Госномер» или «Агрегат» | проверка в UI (см. ниже) |
| `autofill` по `name` / `article` / `code_aa` (справочник номенклатуры) | выбор одного поля подтягивает остальные + ед. изм. | уже косвенно: выбор `Номенклатура` из справочника (артикул/код/ед. изм. — реквизиты номенклатуры, колонки только просмотр) |
| `oneOfRequired`: `name` / `article` / `code_aa` | одно из трёх | проверяется как «Номенклатура заполнена» |

Варианты по объёму справочника ТС:
- **A** — существующий объект УНФ (данных об объекте «машина» в репозитории нет, метаданные УНФ недоступны) — не выбран;
- **B** — новый справочник в расширении (метаданные, формы, миграция, права — отдельный объём) — не выбран;
- **C — выбран (принято без остановок):** только ручной ввод полей машины (`Марка`, `Модель`, `Агрегат`, `Госномер`, `VIN`, `Двигатель`, `НомерШасси`) по ACL; нового справочника нет. Возврат к A/B — отдельным решением владельца.

## Что обязательно (MVP)

Источник — бит `required (64)` матрицы (вкладка manager, статусы «Черновик» `new` и «В работе» `in_work`) + `oneOfRequired` из `index.html`:

| Правило | Колонки матрицы |
|---|---|
| Обязательно заполнено | `order_date` (Дата заказа), `order_client_number` (№ заказ клиент), `qty` (Кол-во > 0) |
| Одно из | `name`/`article`/`code_aa` → «Наименование» (Номенклатура); `gosnomer_fact`/`aggregate_fact` → «Госномер» или «Агрегат» |
| В матрице `required`, но не проверяется | `supplier` (Поставщик): относится к строке **закупки**; у строки продажи его нет до закупки. `line_status`: required на статус — это сам переход |

## Реализация (только UI)

Код в `DataProcessor/АС_АРМ2/Form/Форма/Form.obj.bsl`; **не** в `ПриЗаписи` документов, не в `ОбновитьДанныеПоОбъекту`, не в фоне, не в seed (`Арм_ДанныеЗакупокИПродажФон`, создание строк из заказов не тронуты).

1. **Переход статуса** (`УстановитьСтатусСтрокАдминистраторомНаСервере`, кнопки «Статус: резервирование / ожидаем поступление / возврат»): для роли **Менеджер** и строки в «Черновик»/«В работе» — если не заполнены обязательные поля (`НезаполненныеОбязательныеПоляАРМ`), строка пропускается, пользователю — текст «Статус не изменён у строк с незаполненными обязательными полями (N шт.): …». Администратор не ограничивается.
2. **Запись поля** (`ЗаписатьПолеСтрокиАРМ`, общий ввод; не администратор): нельзя **очистить** `ДатаЗаказа`, `НомерЗаказаКлиента`; нельзя очистить последнее заполненное из пары `Госномер`/`Агрегат` (`ОтказОчисткиОбязательногоПоляАРМ`) — только в статусах «Черновик»/«В работе».
3. Не проверяется при записи: `Номенклатура`, `Количество` (пишутся своими процедурами, не общим путём) — проверяются только при переходе статуса.

Побочный эффект, о котором нужно знать на приёмке: строки из seed/заказов без `Госномер`/`Агрегат`/`НомерЗаказаКлиента` менеджер не переведёт кнопкой статуса, пока не заполнит поля (по канону матрицы). Админ — без ограничений.

## Не сделано / открыто

- Autofill по госномеру (вариант A/B) — после решения владельца.
- `Поставщик` required для строк закупки — не реализовано (нужен отдельный путь записи).
- Проверки в процедурах `Изменить*НаСервере` (количество, цена) и в `ЗафиксироватьПоставщика…` — не добавлялись.
- Критерий «регрессия проведения Заказа/РН» — ручная проверка на тест-ИБ ([acceptance-v2.10.md](acceptance-v2.10.md) B8, B10).
