# Задача: ручная пошаговая проверка процессов через PWA и API АРМ

**Цель.** Убедиться руками, что каждый из 11 сценариев `process.html` проходит в PWA (а значит — только запросами
REST API АРМ v2.9): статусы строк меняются как на схеме, права ролей соблюдаются, документы 1С создаются.
Автоматически то же проверяет `node tools/arm-api-1c/e2e-processes.js`; эта задача — для приёмки глазами.

**Где.** Тестовая база `D:\1c\test_fresh` (публикация `/vitauto`). На рабочей базе не выполнять: создаются заказы,
накладные, меняются остатки.

## Подготовка

1. `.\tools\arm-api-1c\start.ps1` — ответ «API работает … (401 без токена — норма)».
2. `.\seed-1c.ps1 -IbDir D:\1c\test_fresh -KeepSafeModeOff` — в итоге «ошибок 0».
3. `cd pwa; npm install; npm run dev:test` → открыть `http://127.0.0.1:5173`.
4. Пользователи (пароль `1`): `arm.manager`, `arm.storekeeper`, `arm.supply`, `arm.admin`, `arm.mechanic`.
   Удобно держать разные роли в разных профилях браузера или окнах инкогнито.

Условные обозначения:

- **Отметить** — галочка в первом столбце строки (её ставит и снимает только тот, кто отметил).
- **Ячейка** — двойной клик по голубой ячейке, ввод, Enter. Ссылочные поля открывают выбор из справочника.
- **Колонки** — кнопка над таблицей; для шага удобно выбрать «Этап процесса» с узлом шага.
- Статус строки — столбец «Статус». Каждый запрос виден в «Журнал» (код, тело ответа).
- При ошибке — всплывающее сообщение с кодом: `403 matrix_denied` (нет прав по матрице), `409 …` (нарушено условие).

## Типовые блоки

**Б1. Заявка (N1, M1)** — `arm.manager`, «Загрузка»: заказчик «АЛЬЯНС», строка
`Т-1<Tab>срочно<Tab>А001АА77<Tab>Склад 1<Tab>ART-1<Tab>Тестовая позиция<Tab>1` → «Загрузить».
Ожидается: открывается карточка заказа; «Строки АРМ по заказу» → строка в статусе «В работе».

**Б2. Подбор (M2)** — `arm.manager`, «Продажи», строка заказа: ячейки «Номенклатура» = «Крышка КАМАЗ редуктора
среднего моста», «Количество» = 1, «Цена себестоимости» (О1) = 500, «Коэфф» (Р1) = 1,3, «Поставщик» (С1) = «ИП Кетчерская».
Ожидается: «Цена продажи» = 650, «Сумма» = 650, «Сумма себестоимости» = 500.

**Б3. Заказ поставщику (M4)** — `arm.manager`: строка продажи текущая → «Закупка к строке» → «Крышка…» → «Выбрать».
«Закупки»: у новой строки ячейки «Количество» 1, «Поставщик», «Цена себестоимости» 500, «Цена продажи» (Р2) 500;
отметить закупку → «В работе». Ожидается: «Готово», закупка и продажа — «Заказано», в закупке номер заказа поставщику.

**Б4. Снабжение до статуса X** — `arm.supply`, «Снабжение»: отметить закупку, нажимать по очереди
«Оплачено» (M7) → «В пути» (P2) → «Приёмка» (K1) → «На склад» (K2) → «Комплектуется» (M9) → «Собран» (K3).
Ожидается после каждой кнопки: закупка и связанная продажа в новом статусе («Собран» = «Готово к отгрузке»);
на «Собран» у закупки появляется приходная накладная (проведена).

**Б5. Со склада до «Готово к отгрузке»** — `arm.manager`: отметить продажу → «Зарезервировать» (M3, «Резервирование»)
→ отметить → «На комплектацию» (M9, «Комплектуется»); `arm.storekeeper`: отметить → «Собрано» (K3, «Готово к отгрузке»).
Требуется остаток на складе: если отгрузка в Б6 ответит «Не удалось провести», сначала пройти Б1–Б4 отдельным
заказом и закрыть его («Закрыть» без отгрузки).

**Б6. Отгрузка и закрытие** — `arm.manager`: строка текущая → «Отгрузка» (M12): дата, номер (до 10 символов) →
«Записать»; отметить продажу → «В работе» (K5). Ожидается: «Отгружено», в строке расходная накладная.
Ячейка «Документ подписан оригинал» (А3; «Колонки» → этап M15) = ✓ → отметить → «Закрыть» (M15/K7) → «Закрыт».
Без ✓ «Закрыть» отвечает `409 transition_denied` «не отмечено «Документ подписан оригинал»».

## Проверки прав (в любом сценарии)

| Проверка | Ожидается |

| `arm.manager` открывает `/lines/supply` | возвращает на «Продажи»; API `GET /lines?view=supply` — 403 |

## Критерии приёмки

1. Все 11 сценариев доходят до итогового статуса из таблицы, без ошибок кроме ожидаемых `403`/`409`.
2. В «Журнале» нет ответов 500.
3. Документы 1С (ЗП, ПН, РН) открываются по ссылкам строк и проведены (карточка документа «проведён»).
4. Проверки прав дают ожидаемые ответы.
5. `node tools/arm-api-1c/e2e-processes.js` — «сценариев 11, пройдено 11»; `cd pwa; npm test` — все тесты пройдены.

Результат: отметить в задаче номера пройденных сценариев; для непройденных — шаг, роль, текст ошибки из «Журнала».
