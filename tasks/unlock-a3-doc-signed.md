# Задача: unlock строки по А3 «Документ подписан оригинал»

## Разрыв (as-is)

- Единственная постоянная блокировка строки в форме `АС_АРМ2` — статус `ЗаблокированоФоном` (выражение `СтрокаЗаблокирована` в обоих динамических списках) плюс временная интерфейсная `СтрокаЗаблокированаИнтерфейс` (ключи из `&ВременноЗаблокированныеКлючи`).
- Поле `ДокументПодписанОригинал` (А3) **ничего не разблокирует**: оно ни в одном выражении блокировки не участвует.
- Отдельная «защита» по автору: `АвторСтроки` + `ОтметкаСтроки` (выбор строки пользователем). Чужую отмеченную строку другой пользователь не может отметить/снять (`ИнвертироватьФлагНаСервере`).

## Предлагаемое правило (следующий scope)

Когда `ДокументПодписанОригинал = Истина`, строка считается редактируемой для админских полей, даже если ранее была «защищена» автором или статусом (кроме `ЗаблокированоФоном` — это техническая блокировка фоновым заданием, её А3 не снимает).

Нужно решить отдельно:
- какие статусы строки допускают unlock (только `Отгружено`? любые?);
- что с обратным переключением А3 `Истина → Ложь` (возвращать защиту?);
- нужен ли флаг в динамических списках (`СтрокаЗаблокирована` с учётом А3) и условное оформление.

## Что сделано в v2.10 (минимум)

В `Form.obj.bsl` → `ЗаписатьПолеСтрокиАРМ`: при записи `ДокументПодписанОригинал = Истина` у строки (только администратор) очищаются `АвторСтроки` (пустая ссылка) и `ОтметкаСтроки` (чтобы не осталась отметка без автора). Больше никаких блокировок не менялось.

Проверка `АвторСтроки` в `ИнвертироватьФлагНаСервере` и выборках «мои отмеченные» остаётся как есть — после сброса автора строка снова свободна для отметки любым пользователем.

## Критерии приёмки

- [ ] Администратор ставит А3 = Истина у строки, отмеченной другим пользователем → автор и отметка сброшены, строка доступна для отметки.
- [ ] А3 = Ложь автора не возвращает (ожидаемо в v2.10).
- [ ] Строки в `ЗаблокированоФоном` по-прежнему не редактируются.
- [ ] Принято решение по полному правилу (см. «Нужно решить»).
