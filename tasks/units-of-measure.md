# Задача: единицы измерения (шт / л / …) — выпадающий список

**Статус (05.10.2026):** вопросы закрыты решением D5 (без остановок), реализация в `src/АРМЗакупокИПродаж_v2.11` (T09). Ручная приёмка — [acceptance-v2.10.md](acceptance-v2.10.md) B9. Источник: диалог 02.10.2026; вне scope `price-qty-sum.md`.

## Решения (D5)

| Вопрос | Решение |
|---|---|
| 1. Хранение | **Строка** в `Арм_ДанныеЗакупокИПродаж.ЕдиницаИзмеренияКлиента` (String 10, как было); ни перечисления, ни справочника, миграция данных не нужна |
| Список | **6 значений из `index.html`** (`DIRECTORIES.units`): `шт`, `компл`, `л`, `кг`, `м`, `н/ч` |
| 2. Пересчёт количества при смене единицы | **Нет.** Единица информационная; `Количество`/`КоличествоКлиента`/суммы не пересчитываются |
| М4 «Ед. изм.» (единица номенклатуры, `НоменклатураЕдиницаИзмерения`) | **Остаётся только просмотр** — данные справочника из АРМ не меняем |
| 3. Роли | По ACL колонки К7 (`unit_fact`): менеджер, главный механик, админ — только в «Черновик»/«В работе» (маска 13); в остальных статусах по матрице нет; админ — whitelist без привязки к статусу (D1e=B) |
| 4. Совместимость со старыми значениями | Уже введённые строки и seed (`шт`, `л`, `н/ч` — в списке) не трогаются; значение вне списка остаётся как есть, пока его не изменят; запись нового значения вне списка сервер отклоняет |

## Реализация

- `Form.obj.bsl`: `СписокЕдиницИзмеренияАРМ()` = `"шт,компл,л,кг,м,н/ч"`.
- `ОбработатьВыборАдминистратора`: для `ЕдиницаИзмеренияКлиента` после проверки ACL — `ПоказатьВыборИзСписка` (6 значений, текущее выделено) вместо свободного ввода; результат → `ПослеВыбораЕдиницыИзмерения` → общая запись `ЗаписатьПолеСтрокиАРМ`.
- `ЗаписатьПолеСтрокиАРМ`: серверная проверка «значение из списка» (пустое допускается).
- `ПрименитьКолонкиПоМатрице`: у администратора колонка не редактируется прямо в ячейке (чтобы не вводить текст вне списка) — только двойной щелчок и выбор из списка.
