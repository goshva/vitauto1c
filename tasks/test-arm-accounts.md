# T12a — Тестовые учётки АРМ и защита seed от боевой ИБ

**Статус (05.10.2026):** документ + защита в `seed-1c.ps1`. **Пароли в git не хранятся** (ни здесь, ни в `seed/`, ни в `1c-env.json`). Seed на боевой базе не запускался и не запускается.

## Как роль АРМ определяется в 1С

Роль берётся **строго** из регистра `Арм_ПраваПользователей` по текущему пользователю (`ПараметрыСеанса.ТекущийПользователь`, элемент `Справочник.Пользователи`). Записи нет → отказ по всем ACL-путям (D1b). Seed создаёт элементы справочника и записи регистра, но **не создаёт пользователей информационной базы (логин/пароль)** — их заводит тестировщик в конфигураторе/«Пользователи» тест-ИБ и связывает с элементами справочника.

## Предполагаемые учётки (тест-ИБ)

| Роль АРМ (`Арм_РолиИнтерфейса`) | Колонка матрицы | Элемент справочника (seed) | Предлагаемый логин ИБ | Что проверять |
|---|---|---|---|---|
| Менеджер | manager | «Менеджер (seed)» | `arm_manager` | основной сценарий, ACL, T08 (обязательные), А3 |
| Кладовщик | storekeeper | «Кладовщик (seed)» | `arm_storekeeper` | приход, дата УПД, А3 в «Отгружено» |
| Снабжение | = storekeeper (D1d) | «Снабжение (seed)» | `arm_supply` | `ФормаСнабжение`, гейт цепочки закупки (T07) |
| Главный механик | chief_mechanic | «Главный механик (seed)» | `arm_mechanic` | узкие права, отказы |
| Администратор | admin | «Администратор (seed)» | `arm_admin` | whitelist (D1e=B), все кнопки статуса |
| Поставщик | supplier | «Поставщик (seed)» | `arm_supplier` | read-only/минимум |
| Клиент | client | «Клиент (seed)» | `arm_client` | read-only |
| (нет записи в регистре) | — | любой другой пользователь | `arm_norole` | отказ везде (D1b) |

Служебный пользователь для самого seed — `adminUser` из `seed/data.json` («Админ»); пароль — только параметром `-IbPassword`/переменной окружения на машине, не в репозитории.

## Правила

1. Пароли и строки соединения с паролем не коммитятся; `1c-env.json` не должен содержать боевые пароли (проверять перед коммитом).
2. Логины — только в тест-ИБ (например, `D:\1c\test_v211`), не в `C:\1c_bases\...`.
3. Матрица ролей для проверки — [default-matrix.js] / канон `?role=manager&level=order&mode=all` (см. README).

## Защита seed (T12a)

`seed-1c.ps1`: параметр `-AllowProd`; если `-IbDir`, `1c-env.json` или `-ConnectionString` содержат путь `C:\1c_bases\...` (регистр и слэши любые) — скрипт **отказывает** (`throw`). С `-AllowProd` — предупреждение и работа. Без пути `C:\1c_bases` — работа как раньше.

Проверка защиты не выполнялась в рантайме (запуск против боевого пути запрещён политикой проекта); тест `test_seed_has_prod_guard` проверяет наличие кода по тексту. Ручная проверка: `.\seed-1c.ps1 -IbDir C:\1c_bases\x` должен немедленно упасть с «Отказ: база выглядит боевой» до любых подключений.
