## Предложение MVP (минимум, не «полный возврат»)

Цель MVP — **зафиксировать факт и причину возврата строки и вести её по статусам**, не трогая учёт остатков УНФ.

1. **Один вид возврата в MVP — возврат от клиента (C1).** Возврат поставщику (C2) — после.
2. **Данные:** без новых документов УНФ. В строку регистра добавить (Phase B): `ПричинаВозврата` (строка/перечисление из 3–4 значений: брак, ошибочный заказ, не подошло, прочее), `ДатаВозврата`, `КоличествоВозврата` (число ≤ количества строки). Комментарий — существующее поле.
3. **Статусы:** вход в «Возврат» — уже есть (кнопка, ACL: менеджер по `line_status` + админ). Выход — «Выполнено/Завершено» после приёмки на складе и контроля документов (А3). Новых статусов не добавлять.
4. **Роли:** менеджер инициирует (кнопка + обязательные «Причина»/«Дата»/«Количество»); кладовщик/снабжение фиксирует приёмку возврата на складе (`ДатаВозврата` факт., комментарий) — по маске матрицы для статуса `return`; клиент без права инициации в 1С в MVP (инициация голосом/по телефону → менеджер).
5. **Документы УНФ:** MVP не создаёт «Возврат покупателя» автоматически — ручное оформление в УНФ вне АРМ; в АРМ — только отметка/ссылка (комментарий). Автосоздание документа — Phase C.
6. **Уведомления/печать:** нет (см. [print-notify-scope.md](print-notify-scope.md)).

4. Возврат поставщику (C2) входит в MVP или нет?
5. Нужна ли печать/акт возврата?
