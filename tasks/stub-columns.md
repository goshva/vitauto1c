# T05 — пять колонок-заглушки → поля регистра (v2.11)

**Статус:** реализовано в исходниках `src/АРМЗакупокИПродаж_v2.11` (05.10.2026, решение D4 «без остановок»). CFE на момент записи не пересобран, на ИБ не грузилось; платформы 1С в среде нет — проверен текст/данные тестами (`tools/test_arm_matrix_rights.py`), не исполнение BSL.

## Что стало

Существующих полей под эти колонки в `Арм_ДанныеЗакупокИПродаж` **не было** (`ГРЗКлиента` — это «Машина ГРЗ (ФАКТ)» К2, а не № шасси Е5; `ОстатокДляСтроки`/`ОстатокТовара` — склад, не резерв). Добавлены 5 ресурсов (скрипт `tools/add_stub_register_fields.py`, идемпотентный; блоки клонированы с соседних ресурсов, новые uuid, счётчик ресурсов 47 → 52):

| Колонка (код) | id матрицы | Поле регистра | Тип | Было |
|---|---|---|---|---|
| № Шасси (Е5) | `grz_fact` | `НомерШасси` | Строка 50 | `ЗаглушкаНомерШасси` = `""` |
| Кол-во в резерве (Н2) | `reserve_qty` | `КоличествоВРезерве` | Число 15.3 | `ЗаглушкаКолВРезерве` |
| Кол-во заказанного в пути (Н3) | `ordered_in_transit_qty` | `КоличествоВПути` | Число 15.3 | `ЗаглушкаКолВПути` |
| Дата УПД (С3) | `upd_date` | `ДатаУПД` | Дата | `ЗаглушкаДатаУПД` |
| № УПД (С4) | `upd_number` | `НомерУПД` | Строка 50 | `ЗаглушкаНомерУПД` |

- `Form.obj.bsl` → `ОписаниеКолонокПоМатрице()`: вид колонок `С` → `Р` (поле регистра в запросе списка `ОсновнаяТаблица.<Поле>`), заглушек больше нет (`"" КАК …` не генерируется). Имена `Заглушка*` убраны и из `Арм_МатрицаПрав` (`СписокПолейМатрицы`) — генератор `tools/generate_arm_matrix_rights.py` перегенерирован.
- Данные по существующим строкам: новые ресурсы пустые (`0` / пусто / пустая дата).

## Запись (ACL, не «только админ»)

Новая функция формы `ПоляВводаПоACL()` = `НомерШасси, КоличествоВРезерве, КоличествоВПути, ДатаУПД, НомерУПД` (совпадает с `Арм_МатрицаПрав.ПоляВводаПоACL()`, проверяет тест). Путь: двойной щелчок → `ОбработатьВыборАдминистратора` (клиентская проверка `ОтказПоПравамАРМ`) → `ПоказатьВводЗначения` по типу поля → `ЗаписатьПолеСтрокиАРМ` (серверная проверка роль × статус × поле). В whitelist администратора (`ПоляРедактируемыеАдминистратором`, D1e=B) поля **не добавлены** — у admin на этих колонках в матрице нет права.

Кто что может по матрице (вкладка manager, уровень order; бит: manager=1, storekeeper=2, admin=8):

| Поле | Роль → статусы строки |
|---|---|
| `НомерШасси` (Е5) | Менеджер — «Черновик», «В работе»; остальные — нет |
| `ДатаУПД`, `НомерУПД` (С3, С4) | Кладовщик/Снабжение (бит 2) — «Приходуется», «На складе»; остальные — нет |
| `КоличествоВРезерве` (Н2), `КоличествоВПути` (Н3) | **никто** (RO во всех статусах и ролях) → только системный fill; источника пока нет (см. ниже). Путь ввода откроется автоматически, если матрицу перегенерировать с правом на эти колонки |

## Источники (D4)

1. **Ручной ввод** — по таблице выше.
2. **УПД из приходной накладной** — разведка: в репозитории (расширение v2.11, документы, docs) метаданных конфигурации УНФ нет, реквизиты `Документ.ПриходнаяНакладная` для УПД не описаны (grep по `УПД`, `НомерВходящегоДокумента`, `ДатаВходящегоДокумента` в BSL расширения — пусто). Поэтому реализована **условная** подстановка `Арм_ОбщегоНазначенияАРМ.ЗаполнитьУПДИзПриходнойЕслиЕсть(ЗаписьРегистра)`: в рантайме ищет в метаданных ПН реквизиты-кандидаты (дата: `ДатаВходящегоДокумента`, `ДатаУПД`, `ДатаДокументаПоставщика`; номер: `НомерВходящегоДокумента`, `НомерУПД`, `НомерДокументаПоставщика`) и, если нашёлся, заполняет пустые `ДатаУПД`/`НомерУПД` при связывании строки закупки/продажи с ПН (там же, где пишется `ДокументПриходнаяНакладная`). Нет реквизитов — функция ничего не делает, остаётся ручной ввод. **Не проверено на реальной УНФ:** ПН создаётся программно из АРМ, номер входящего документа в этот момент, скорее всего, пуст — подстановка «догонит» только данные, уже введённые в ПН до связывания. Повторной синхронизации нет.
3. **Шасси** — позже может заполняться из справочника машин (T08, вариант C выбран: только ручной ввод).
4. **Резерв / в пути** — реального резервирования остатков УНФ нет и не обещается ([impl-plan, «Вне плана»](impl-plan-matrix-arm.md)); поля существуют как место под будущий системный fill.

## Оговорки

- `ОбновитьДанныеПоОбъекту` (регистр, `Арм_ДанныеЗакупокИПродаж.ОбновитьДанныеПоОбъекту`) пересобирает набор записей документа из табличной части; все ручные поля строки (марка, госномер, теперь и новые) при перепроведении документа могут обнуляться — **существующее поведение v2.10**, T05 его не меняет. Проверить на приёмке (чек-лист B5, [acceptance-v2.10.md](acceptance-v2.10.md)).
- Права **ролей 1С** (объектные права на ресурсы регистра) для новых ресурсов не менялись: роли расширения `Арм_Пользователь`, `Арм_ОсновнаяРоль`, `Арм_Администратор` (`Role/*`) не трогались; при необходимости выдать чтение/запись новых ресурсов — отдельным шагом на тест-ИБ.
- Метаданные регистра правились скриптом на сыром v8unpack-JSON; перед использованием — repack `.cfe`, `CheckModules`, `UpdateDBCfg` на тест-ИБ.
