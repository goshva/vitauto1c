3. План ручного тестирования

Перед стартом: тестовая база (не боевая), расширение v2.11 загружено, безопасный режим выключен, в АРМ есть строки (seed на эту же test-ИБ). Результаты удобно писать в acceptance-v2.10.md.

Шаг 0. Подготовка

  1. Скопировать/указать путь тестовой ИБ (не C:\1c_bases\autoservice без отдельного ок).
  2. LoadCfg: файл АРМЗакупокИПродаж_v2.11.cfe → обновить конфигурацию БД.
  3. Проверить: расширение не в безопасном режиме.
  4. При необходимости прогнать seed на эту test-ИБ (seed-1c.ps1 -IbDir …, без -AllowProd на боевую).
  5. Убедиться, что у тестовых пользователей есть запись роли в регистре прав АРМ (см. test-arm-accounts.md).

Блок A — регресс «как раньше» (v2.10-поведение внутри v2.11)

Проверять под Администратором, если не указано иное.

  1. АРМ открывается, в заголовках колонок видны коды матрицы (Е4, Р2…), порядок колонок привычный.
  2. Меняются цена / количество — пересчитываются суммы (себестоимость и продажа).
  3. «Договор с заказчиком»: видны только договоры выбранного заказчика; чужой выбрать нельзя.
  4. Смена заказчика очищает договор, если он был от другого контрагента.
  5. Отгрузить строку → появился номер отгрузки из расходной накладной; вручную номер ввести нельзя.
  6. Диалог даты отгрузки: можно задать дату; поля номера в диалоге нет (или оно скрыто).
  7. Кнопки «Статус: резервирование / ожидаем / возврат» работают на отмеченных (или текущей) строках.
  8. Галка «Документ подписан оригинал» сбрасывает автора строки и отметку.

Блок B — права (главное в v2.11)

  1. Менеджер, статус «Черновик» / «В работе»: может менять заказчика, номенклатуру, количество, цену, коэффициент, комментарий — значения сохраняются.
  2. Менеджер, статус «Заказано» (или другой «поздний»): попытка сменить заказчика / количество — отказ с понятным текстом (роль / статус / поле).
  3. Менеджер, «Отгружено»: можно поставить «Документ подписан»; количество менять нельзя.
  4. «Номер отгрузки» не редактируется ни у менеджера, ни у админа.
  5. Менеджер на «Черновик» жмёт «Статус: резервирование» — статус меняется; на статусе, где матрица запрещает — отказ.
  6. Пользователь без роли в регистре прав АРМ: форма открывается, любая правка — отказ «не задана роль».
  7. Клиент: может править комментарий; заказчика / цену — нельзя.
  8. Админ: широкий набор полей правится; номер отгрузки и смена статуса «из ячейки» — нет; кнопки статусов — да.

Блок C — новые колонки и ед.изм.

  1. В таблице видны колонки: № шасси, кол-во в резерве, кол-во в пути, дата УПД, № УПД (не пустые «заглушки»-константы).
  2. Менеджер в «Черновик»/«В работе» вводит № шасси — сохраняется; в чужом статусе — отказ.
  3. Кладовщик (или снабжение по вашей схеме) в статусах приёмки/склада вводит дату и № УПД — сохраняется.
  4. «Ед. изм. (ФАКТ)»: двойной щелчок → список шт / компл / л / кг / м / н/ч; количество само не прыгает.
  5. Колонка «Ед. изм.» номенклатуры (М4) только для просмотра.

Блок D — снабжение и обязательность

  1. Под ролью Клиент или Поставщик на форме снабжения кнопки смены статусов закупки / отметки — отказ.
  2. Под Менеджер / Снабжение / Кладовщик / Админ цепочка снабжения работает как раньше (дымок).
  3. Менеджер, «Черновик» без госномера и без агрегата → «Статус: резервирование» — отказ с перечнем незаполненного (если так задумано в T08).

Блок E — сквозной дымок документов

  1. Записать/провести заказ покупателя — строки появляются/обновляются в АРМ без ошибок журнала.
  2. Довести до отгрузки — расходная накладная, статус «Отгружено», номер отгрузки заполнен.
  3. В журнале регистрации нет ошибок «поле не найдено» по новым реквизитам (НомерШасси, ДатаУПД…).
  4. Фоновое «ЗаблокированоФоном»: строку править нельзя, пока фон не отпустил.

Как фиксировать результат

  • По каждому пункту: pass / fail / skip + коротко «что увидели».
  • Баги: приоритет P0 (блокирует работу) / P1 / P2 + шаги воспроизведения.
  • P0 → чинить hotfix’ом на ветке; потом снова блок B/E.
  • Если всё зелёное → можно обсуждать merge в dev.
