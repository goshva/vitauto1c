# Задача: колонки АРМ продаж по матрице — отображение и запись в базу для роли «Администратор»

## Цель

В таблице продаж АРМ (обработка `АС_АРМ2`, форма `Форма`, список `ДанныеАРМОтображение`) администратор видит все 50 колонок матрицы с нужными заголовками и в нужном порядке. Колонки, которые матрица разрешает ему редактировать, он может изменить, и значение сохраняется в базе. После повторного открытия формы значение то же.

**Логики пока нет.** Статусы, правила полей и обязательность в этой задаче не учитываются.

## Источники

| Что | Где |
|---|---|
| Канон матрицы (порядок и заголовки колонок) | `index.html` |
| Настройки ролей, статусов и прав | `column-matrix (5).json` (выгрузка от 26.09.2026) |
| Текущая реализация | расширение `АРМЗакупокИПродаж_v2.0.cfe`, модуль формы `Обработка.АС_АРМ2.Форма.Форма`: `ОписаниеКолонокПоМатрице()`, `ПрименитьКолонкиПоМатрице()` |
| Хранение строк | регистр сведений `Арм_ДанныеЗакупокИПродаж` |
| Роль интерфейса пользователя | регистр сведений `Арм_ПраваПользователей`, перечисление `Арм_РолиИнтерфейса` |

## Границы задачи

**Входит:**
- роль «Администратор» (`admin` в матрице) и только уровень статуса «Заказ» (`order`);
- отображение всех 50 колонок: заголовок, порядок, тип поля;
- редактирование колонок, которые матрица разрешает администратору хотя бы в одном статусе (колонка «Админ: редактирование» в таблице ниже, 37 колонок);
- запись изменённого значения в `Арм_ДанныеЗакупокИПродаж` и чтение его обратно;
- 13 колонок, которые администратор не редактирует ни в одном статусе, — только просмотр.

**Не входит** (следующие задачи):
- зависимость прав от статуса строки: для админа права сейчас одинаковы во всех статусах;
- правила полей из `fieldRules`: списки значений, отбор договора по заказчику, автозаполнение марки, модели, VIN и двигателя по госномеру, «Госномер или Агрегат обязателен»;
- обязательность (`required`);
- остальные роли: менеджер, кладовщик, главный механик, снабжение, поставщик, клиент;
- расчётные колонки: резерв, в пути, № шасси, дата и № УПД. Они показываются пустыми, данные для них — в отдельной задаче;
- справочники для колонок «Выбор» у фактических данных автомобиля. Пока это строки, ссылочные типы — позже.

## Что сделать

В `ОбработкаПолученияФормы` модуля менеджера `АС_АРМ2` для этой роли открывать форму `Форма`, как для менеджера. В форме завести признак «режим администратора». Пользователь без записи в `Арм_ПраваПользователей` остаётся менеджером, как сейчас.
2. **Отображение.** Все 50 колонок видимы, в порядке и с заголовками из таблицы ниже. Сейчас это делает `ОписаниеКолонокПоМатрице()`, её нужно сверить с таблицей. Тип поля:
   - «Флажок» — поле флажка;
   - «Число» и «Дата» — поле ввода соответствующего типа;
   - «Строка» и «Выбор» — поле ввода.
3. **Хранение.**
   - Добавить в регистр `Арм_ДанныеЗакупокИПродаж` 11 новых ресурсов: строки «**добавить**» в таблице.
   - Колонку «Договор с заказчиком» перевести на существующее поле `Договор`.
   - Колонку «№ п/п» — на существующее поле `Порядок`.
   - Для колонки «Дата получения» проверить, что существующее поле `ДатаПоступления` — это она.
   - Для колонок, получивших поле регистра, убрать заглушки из запроса списка. Для этого поправить `ПрименитьКолонкиПоМатрице()`: вставка `"" КАК …` и `ЛОЖЬ КАК …`.
4. **Редактирование и запись.**
   - Для администратора снять `ТолькоПросмотр` с колонок «да» в таблице.
   - Изменённое значение записывать в строку регистра через существующий механизм записи набора записей в модуле формы (процедуры с `РегистрыСведений.Арм_ДанныеЗакупокИПродаж.СоздатьНаборЗаписей()`), дополнив его новыми полями.
   - После записи обновлять список.
5. **Права 1С.** У роли `Арм_Администратор` должно быть право изменения регистра `Арм_ДанныеЗакупокИПродаж`, включая новые ресурсы.

## Расхождения, найденные при подготовке задачи

1. **В `column-matrix (5).json` 49 колонок в списке `columns`, в матрице — 50.** В списке нет «Агрегат» (`aggregate_fact`), хотя в матрице и в `index.html` колонка есть. В самом файле она стоит последней, в `index.html` и в форме — после «Модель». В задаче принят порядок `index.html`. Выгрузку лучше повторить из актуального `index.html`.
2. **«Поле выбора ячеек» (`cell_select`) в форме без заголовка.** В форме это колонка отметки строки, в матрице у неё подпись «поле выбора ячеек». Решить, нужен ли заголовок.
3. **«Артикул», «Код А-А / код поставщика», «Ед. изм.»** матрица разрешает администратору править в одном статусе, но это реквизиты справочника «Номенклатура», а не строки заказа. В этой задаче они только показываются. Нужно решение: править справочник из АРМ или хранить значение в строке.
4. **На уровне «Деталь» (`line`)** администратор в выгрузке не редактирует ни одной колонки ни в одном статусе. Проверить, так ли задумано. В этой задаче уровень «Деталь» не используется.
5. **«№ Шасии»** администратор не редактирует ни в одном статусе: по `fieldRules` колонка заполняется автоматически при выборе госномера. В этой задаче автозаполнения нет, поэтому колонка пустая. Опечатку в заголовке («№ Шасии» вместо «№ Шасси») стоит исправить в `index.html` и в форме одновременно.
