## Детали

### BUG-1 — обрезка номера заказа (P2)
- Факт: `Арм_ДанныеЗакупокИПродаж.НомерЗаказа` — Строка(10), номер ЗаказаПокупателя 11 символов → в регистре теряется последний символ, поиск/связка по номеру ненадёжны.
- Код: МодульМенеджера регистра, стр. 62 `НоваяЗапись.НомерЗаказа = РеквизитыКонтрагентИДоговор.Номер;`.
- Фикс: длина реквизита 20 (изменение структуры расширения → UpdateDBCfg); перезаполнить существующие записи обработкой из Ссылки заказа.
- Проверка: check-data BUG-1 → 0 предупреждений.

### BUG-2 — скрытые отмеченные строки (P1)
- Факт: `ПолучитьМассивОтмеченныхКлючейСвязи` фильтрует только по Автору, без отбора формы (период). Строки, отмеченные раньше и скрытые фильтром, обрабатываются «Заказать»; в ручном прогоне это дало ошибку по невидимой строке. `ВычеркнутьСтрокуНаСервере` — так же: можно вычеркнуть невидимую строку. Снять флажок у скрытой строки из UI нельзя.
- Фикс: (а) брать отмеченные только из видимых данных формы (или накладывать тот же отбор периода/вида); (б) при обновлении фильтра — снимать отметки автора со строк вне периода или показывать счётчик «отмечено скрытых: N» с кнопкой «Снять все мои отметки»; (в) то же в OData /sales/jobs — уже передаёт ids явно, проверить, что фон не добирает отметки сам.
- Тест: m19 расширить — отметка вне периода + «Заказать» по видимым → скрытая не тронута.

### BUG-3 — завышенный остаток (P1)
- Факт: `ПересчитатьОстаткиПоСтрокам`, временная `втСкладскиеОстатки` — LEFT JOIN `РегистрНакопления.Запасы` по Партии (+ Приход) размножает остаток для пустой партии: 179 вместо 9. m06: 11 шт при остатке 10 → не делится, закупка не создаётся.
- Фикс: брать `РегистрНакопления.Запасы.Остатки(, Склад/Номенклатура)` агрегатом СУММА по Номенклатуре+Складу без соединения с партиями; партии — отдельным запросом только если нужны цены.
- Тест: m06 (11 при остатке 10 → сплит 10 + закупка 1); check-data DATA-7.

### BUG-4 — сплит не пишет остаток (P1)
- Факт: v2.19, при сплите остаток → новый документ, `НовыйДокОбъект.Записать(РежимЗаписиДокумента.Проведение)` падает «Номенклатура не может быть пустым» (ГрафикДвиженияЗапасов), если в документе есть строки без Номенклатуры.
- Фикс: проводить только если все строки заполнены, иначе `Записать(Запись)` + сообщение пользователю; обернуть в попытку с откатом транзакции целиком.
- Тест: m05 перевести с «known bug» на нормальное ожидание.

### BUG-5 — себестоимость (P1)
- а) Пересчёт остатков перезаписывает `СебестоимостьЕдиницы` средней по складу (1204.55 / 1221.30 / 1225.17), хотя менеджер ввёл свою; Цена продажи не меняется → маржа плывёт.
- б) Сумма `Себестоимость` не равна Кол×СебЕд у строки 11 шт: 13250 ≠ 11×1204.55 (зеркало), 13476.84 ≠ 11×1225.17 (файловая) — сумма пересчитана от одной цены, единица от другой (сплит/пересчёт меняют их в разных местах).
- Фикс: перезаписывать СебЕд только если поле пустое/0 или строка авто; любой пересчёт единицы — в одной процедуре, которая сразу делает `Себестоимость = Окр(Кол × СебЕд, 2)`.
- Тест: check-data DATA-5 → 0 ошибок; m06 проверка сумм.

### BUG-6 — роль в OData (P1)
- Факт: `ОтказЕслиНеМенеджерИлиАдминАРМ` вызывается только в форме; OData `ВРаботе` и `СформироватьЗаказыФоновоеЗадание` её не проверяют → arm.storekeeper создаёт ЗП (m08).
- Фикс: проверка в начале фоновой процедуры (единая точка) + 403 в API до постановки задания.
- Тест: m08 → ожидать 403 forbidden.

### F-1 — вычеркнутая строка остаётся в заказе покупателя (P1)
- Факт (m13): вычеркивание (PWA DELETE /lines, кнопка «Вычеркнуть товар») ставит у строки АРМ только Удаление; строка остаётся в табличной части Запасы документа ЗаказПокупателя («строк в документе 2», ожидалась 1) → клиенту выставят вычеркнутый товар.
- Фикс: при вычеркивании удалять строку из ЗаказПокупателя.Запасы по КлючуСвязи (Номенклатура — составной тип!), перезаписать документ с тем же режимом (проведён → проведение); если уже есть РН/отгрузка — запрет с сообщением. Связанную авто-закупку статуса new тоже снимать.
- Тест: m13.

### F-2 — сирота-закупка после смены номенклатуры (P2)
- Факт (m15): продажа Диск → вручную добавлена закупка Диска → номенклатура продажи сменена; `ОчиститьАвтоматическиеЗакупки` чистит только авто, ручная закупка Диска остаётся (статус new) без смысла.
- Фикс: при смене номенклатуры продажи — для ручных закупок статуса new с другой номенклатурой спросить/пометить (в OData — вернуть warning `orphan_purchases`); не трогать уже заказанные.
- Тест: m15 (ожидание после решения: закупка удалена или помечена).

### F-3 — отгрузка без даты/номера (P3, вопрос требований)
- Факт (m16): «Провести заказ» без «Ввести дату и номер отгрузки» создаёт РН и переводит в shipped.
- Варианты: обязательность даты/номера для отгрузки или подстановка текущей даты + номер РН. Спросить бизнес.

### F-4 — OData не создаёт авто-закупку (P2)
- Факт: в форме при нехватке остатка `ПересчитатьОстаткиПоСтрокам → УправлятьСтрокойЗакупки` создаёт строку закупки; через OData PATCH количества/номенклатуры этого не происходит (в тестах закупку добавляем POST /lines).
- Фикс: вынести пересчёт+управление закупкой в общий модуль и вызывать из PATCH /lines (после BUG-3, иначе остаток неверный).

### F-5 — пакет «всё или ничего» (P3)
- Одна невалидная строка (например, без поставщика) отклоняет весь пакет «Заказать». По дизайну, но вместе с BUG-2 падает из-за невидимой строки.
- Фикс: в сообщении об ошибке — номер заказа/наименование виновной строки + кнопка «Показать строку»; обсудить режим «заказать валидные, отчитаться по остальным».

### F-6 — неоднозначность статусов PWA (P3)
- PWA маппит «Подготовлено» и «Собран» в `ready_to_ship`; нельзя отличить подготовленную со склада продажу от собранной закупки. Тест m23 принимает оба значения.
- Фикс: отдельный статус `prepared` в API (+ обновить PWA фронт).

### UX — из ручного прогона пользователя (P3)
- UX-1: пользователь не нашёл кнопку «Обновить» — вынести на панель обеих таблиц / автообновление после «Заказать».
- UX-2: правят К6 «Кол-во (ФАКТ)» вместо Н0 «Кол-во» — подсказка в заголовке/закраска клиентских ФАКТ-колонок как только-чтение.
- UX-3: «Заказать» (закупки) и «Провести заказ» (продажи) вызывают одну команду ВРаботе — различать тексты подтверждения/результатов.
- UX-4: загрузка из Excel берёт данные со 2-й строки — заголовок в 1-й обязателен; при вставке без заголовка первая строка теряется. Добавить проверку «первая строка похожа на заголовок».
